# 【Agent 需求文档】SKILL

> **适用产品类别**：A 类（对话式 AI / Agent 产品）为主，C 类（AIGC 多模态生成）、D 类（AI 评测平台）为辅。
> **为什么**：A 类产品的最小单元就是"一个能被用户直接对话的 Agent"，必须单独成文档讲清楚它是谁、解决什么、怎么跑、怎么测；C 类产品中的"生图/生视频 Agent"同理；D 类产品中被评测的 Agent 也需要这份文档作为评测基线。
> **文档目的**：给研发、算法、测试、业务方一份"可以直接搭出这个 Agent"的契约——它的人设、输入输出、流程、工具、Prompt、验收门槛一次写清，不再靠口头对齐。
> **撰写时机**：产品概念已通过立项评审、首个 Agent 进入 MVP 开发前；在 ChatFlow / Workflow 真正开始搭节点之前完成。

---

## 一、撰写前需要收集的资料清单

### 1.1 用户侧
- 这个 Agent 要服务的 **典型用户画像**（至少 2-3 类，含使用频率与付费意愿）。
- 用户在什么 **场景** 下会打开这个 Agent（一句话场景，例如"学员备考面试前 30 分钟"）。
- 用户必须提供的 **初始输入**（文字 / 图片 / 语音 / 文件 / 上传商品图等）。
- 用户对 **输出形式** 的期待（纯文本、Markdown、流程图、多图、JSON、语音）。

### 1.2 业务侧
- Agent 的 **一句话定位**（Name + Description，能直接写进 Dify / Coze / 自研平台）。
- 它要解决的 **核心业务指标**（面试通过率、生成图采纳率、判分准确率、客服解决率等）。
- 是否存在 **子 Agent 分工**（主 Agent + 若干专职 Agent，例如 proposal Agent / generate Agent）。
- 是否需要 **长期记忆 / 会话变量**（跨轮暂存、用户画像沉淀、历史订单引用）。
- 业务上 **不能让 Agent 做什么**（红线：不能替用户做决定、不能泄露内部资料、不能讲出标准答案）。

### 1.3 技术侧
- 计划使用的 **编排平台**（Dify / Coze / 自研 LangGraph / 其他）与应用类型（ChatFlow / Workflow / Agent）。
- **大模型选型**（厂商、版本、是否区分对话/推理/生图节点）。
- 需要调用的 **工具清单**：知识库（Embedding 模型 + Rerank 模型 + Top-K）、联网搜索、代码解释器、MCP 工具、第三方 API。
- **多模态能力**：是否需要图片输入、语音 ASR/TTS、生图 / 生视频模型。
- 预期的 **延迟与成本约束**（在线对话 vs 异步生成，单轮 token 预算）。

### 1.4 数据侧
- 用来做 **测试 Case** 的典型对话样本（≥10 条，覆盖每个功能分支）。
- 用来做 **意图路由** 的分类标签表（例如 CLASS1~CLASS5）。
- 已经存在的 **知识库 / 数据集**（课程知识库、商品图、话术库），以及它们的版本号。
- 业务专家标注的 **正确答案 / 期望输出样本**（用于判分和 Golden Set）。

## 二、资料来源渠道

| 信息类型 | 主要来源 |
|---|---|
| 用户画像与场景 | 用户访谈记录、问卷调查、销售/客服一线工单 |
| Agent 定位与红线 | 立项报告、产品总纲、业务方一对一对齐 |
| 流程分支与意图分类 | 旧版 PRD、竞品体验拆解、白板脑暴 |
| 工具与模型选型 | 算法 / 工程同事、平台官方文档、历史项目复用清单 |

| 指标门槛 | 历史项目基线、业务方 OKR、评测平台 badcase 库 |
| Sys Prompt 写法 | 已上线同类 Agent 的 Prompt 仓库、Prompt Engineering 文档 |

## 三、完整框架结构（七段式，到三级标题）

> 标准骨架：**Agent 概述 → 目标用户 & 适用场景 → 输入输出 → Workflow → 测试 Case（含指标门槛）→ 预期效果 → Sys Prompt**。
> 每一段都不能省；C 类（生图 Agent）在"测试 Case"后可再加一节 **Benchmark（优质参考样例）**。

### 3.1 Agent 概述

- **这一节写什么**：用 3-5 行把这个 Agent 是谁、能干嘛、不能干嘛说清楚。包含 **Name、Description、Hierarchies（若有子 Agent）**。
- **颗粒度要求**：Description 必须是"一句话能扔进系统提示词开头"的完整句，不是形容词堆砌；若有子 Agent，要列出每个子 Agent 的名字和分工。
- **填写要点**：
  - Name 用英文 snake_case 或产品代号，和平台里的 Agent 实例名一致。
  - Description 第一句必须是角色定位（"你是一个……"），第二句写核心能力，第三句写闭环价值。
  - 多 Agent 协作时，明确谁是主入口、谁是被 handoff 的执行方。
- **示例片段**：
  ```
  Name：{agent_name}
  Description：你是一个基于 {平台} 搭建的 {产品定位}。以{核心知识库/数据源}为核心，
  提供{能力1}、{能力2}、{能力3}、{能力4}、{能力5} 五大能力，
  形成"{用户旅程闭环}"，帮助{目标用户}完成{核心任务}。
  Hierarchies：
    - {sub_agent_1}：负责{规划/提案}
    - {sub_agent_2}：负责{执行/生成}
  ```

### 3.2 目标用户 & 适用场景

- **这一节写什么**：分三块——**目标用户**（画像）、**用户需提供的制作素材**、**适用场景清单**。
- **颗粒度要求**：每类用户写 2-3 行背景与痛点；场景要写成"当用户想做 X 时"的具体动作，不要写"提升效率"这种空泛词。
- **填写要点**：
  - 目标用户至少 2 类，避免只写"所有用户"。
  - 适用场景建议 3-5 条，每条对应 Workflow 里的一个分支。
  - 用 callout / 卡片分组展示，方便研发一眼看到。
- **示例片段**：
  ```
  🎯 目标用户
  - {用户角色1}：{背景与痛点，例如需要系统复习知识点、备考转行面试}
  - {用户角色2}：{背景与痛点，例如预算有限但追求高质量商品展示的中小商家}

  🎬 制作内容
  用户需提供 {每日学习笔记 / 单个商品图 / 合同原文}，
  用于生成 {知识库 / 商品场景图 / 风险审阅报告}。

  💡 适用场景
  - {场景1：例如课程知识点复习与面试模拟}
  - {场景2：例如电商主图与详情页场景图生成}
  - {场景3：例如知识体系梳理（思维导图）}
  ```

### 3.3 输入输出

- **这一节写什么**：用一张 6 列表格定义每个 Agent（含子 Agent）的 **必选输入 / 可选输入 / 选项 / 输出类型 / 输出说明**。
- **颗粒度要求**：写到"用户在聊天窗口以什么形式输入、Agent 返回什么格式"的级别；多模态产品必须列出图片/语音/文件等输入类型。
- **填写要点**：
  - 输入要区分"自然语言意图"和"显式指令"（例如用户说"小测验"就触发出题分支）。
  - 输出类型写清楚：文本 / Markdown / Mermaid 图 / 多图 / JSON / 语音。
  - 输出说明要按意图分支展开，不能只写"回复用户"。
- **示例片段**：
  | Agent | 必选输入 | 可选输入 | 选项 | 输出类型 | 输出说明 |
  |---|---|---|---|---|---|
  | {agent_name} | {自然语言对话：知识点关键词 / 指令"小测验" / 主题词 / 笔记原文 / 知识库外问题} | 无 | 无 | 文本 / Markdown / Mermaid 图 | 按意图输出：{面试题+五段式话术}；{10 道单选及判分解析}；{Mermaid 思维导图}；{带来源的联网回答} |

### 3.4 Workflow

- **这一节写什么**：画清楚主入口、**意图分类器 / 条件分支**、各 LLM 节点、工具调用、子 Agent handoff、会话变量流转。
- **颗粒度要求**：必须到"节点级"——开始节点、条件分支、每个 LLM 节点、知识库检索、工具调用、模板转换、结束回复；跨轮逻辑（会话变量的写入与清空）要单独说明。
- **填写要点**：
  - 先写一段"流程总览"：所有功能共用同一入口，再由条件分支路由。
  - 用 Mermaid flowchart 或白板图展示节点关系。
  - 跨轮状态（例如"答题中"）必须显式说明：用哪个会话变量、什么时候写入、什么时候清空。
  - 多 Agent 时写明 handoff 时机（主 Agent 何时把控制权交给执行 Agent）。
- **示例片段**：
  ```
  {N} 个功能共用同一 ChatFlow 入口。开始节点先经条件分支识别"{状态变量}"
  （{会话变量名} 不为空则直接走判分），否则由问题分类器按意图路由到对应分支；
  小测验通过会话变量 {session_var} 跨轮暂存标准答案，判分完成后清空以恢复正常路由。

  （附 Mermaid 白板图：开始 → 条件分支 → 意图分类 → CLASS1..CLASS{N} → 各 LLM 节点
  → 知识库 / 联网搜索 → 模板转换 → 结束回复）
  ```

### 3.5 测试 Case（含指标门槛）

- **这一节写什么**：先给 **衡量指标清单 + 量化门槛**，再给一张 **典型测试用例表**（编号 / 用户输入 / 预期路由 / 预期输出）。
- **颗粒度要求**：指标必须可量化（≥90%、100%、P95≤2s）；测试用例数量 ≥10 条，覆盖每个功能分支 + 跨轮全链路 + 兜底分支。
- **填写要点**：
  - 指标至少包含：意图分类准确率、知识库召回率 / 判分准确率 / 输出相关性、工具调用成功率、兜底响应成功率。
  - 测试用例要包含"正常输入 / 跨轮接续 / 知识库外问题 / 异常输入"四类。
  - 跨轮用例必须写明"上一轮变量是什么 → 这一轮预期路由 → 变量何时清空"。
- **示例片段**：
  ```
  💡 衡量指标
  - 意图分类准确率 ≥ {90%}（{N} 大分支正确路由）
  - 知识库命中时回答与{业务知识}相关度 ≥ {95%}
  - {判分/生成}准确率 {100% / ≥95%}（标准答案由{某节点}暂存）
  - 联网搜索兜底响应成功率 ≥ {90%}，且回答附带来源链接

  典型测试用例
  | 编号 | 用户输入 | 预期路由 | 预期输出 |
  |---|---|---|---|
  | 1 | "{知识点关键词}" | CLASS{X} {分支名} | {面试官提问清单+五段式话术} |
  | 2 | "{指令：小测验}" | CLASS{Y} 出题 | {10 道基于知识库的题，不泄露答案} |
  | 3 | "1.B 2.C 3.A ..."（接上一轮作答） | 条件分支 → 判分节点 | {得分+逐题解析，随后清空变量} |
  | 4 | "{知识库外的最新问题}" | 兜底联网分支 | {整合回答，附来源 URL} |
  ```

### 3.6 预期效果

- **这一节写什么**：按场景给出"用户动作 → 预期输出"的对照表，让业务方一眼看到交付物长什么样。
- **颗粒度要求**：每个适用场景对应一行；输出描述要具体到格式和长度（"10 道单选"、"Mermaid mindmap"、"150-300 字文案"）。
- **填写要点**：
  - 不要写"提升用户满意度"这类无法验收的话。
  - C 类（生图 Agent）建议在这一节后追加 **Benchmark 小节**：列出"可打 5 分的优质参考样例"在哪些公开平台（Instagram / TikTok / Pinterest）找，分纯产品展示、人机交互两类给样例图。
- **示例片段**：
  | 场景 | 用户动作 | 预期输出 |
  |---|---|---|
  | {面试练习} | 输入知识点关键词 | {面试官提问清单 + 五段式结构化回答话术} |
  | {自我检测} | 输入"小测验"，逐题作答 | {10 道单选题；作答后自动判分并给出逐题解析} |
  | {知识梳理} | 输入主题 | {Mermaid mindmap 语法，聊天窗口直接渲染} |
  | {新知追问} | 知识库未覆盖的问题 | {调用联网搜索，整合最新信息并标注来源 URL} |

### 3.7 Sys Prompt

- **这一节写什么**：这是文档的"代码级契约"，包含 **版本配置总览表**、**各节点 System Prompt 要点表**、**版本迭代记录**。
- **颗粒度要求**：写到"研发可以照着这张表在平台上逐项配置"的级别；每个 LLM 节点的角色、上下文输入、输出格式都要列清。
- **填写要点**：
  - 版本配置总览表必须包含：平台 / 应用类型、大模型、Embedding、Rerank、检索模式、联网搜索工具、知识库分段策略、会话变量。
  - 各节点 Prompt 要点表至少包含：节点名、角色（Role）、输入（Inputs / 上下文来源）、输出要求（Output）。
  - 版本迭代记录按版本号倒序写，每一条说明"这次改了什么、为什么改"。
  - **Agent 提示词六要素** 必须在每个节点的 Prompt 中显式落地：
    1. **Role**：你是谁（例如"AI PM 面试教练"）。
    2. **Inputs**：你能看到什么（例如"上下文 = 知识检索.result"）。
    3. **Action Path**：你按什么步骤做（例如"先列面试官可能问的 5 个问题，再按五段式给话术"）。
    4. **Tool Rules**：什么时候调工具、什么时候不调（例如"知识库命中则不联网；未命中再调 BOCHA"）。
    5. **Output**：输出格式（Markdown / JSON / Mermaid / 特殊标记包裹）。
    6. **Constraints**：红线（例如"不泄露标准答案、不编造来源、不超出角色"）。
- **示例片段——版本配置总览**：
  | 配置项 | 取值 |
  |---|---|
  | 平台 / 应用类型 | {Dify Cloud} / {ChatFlow} |
  | 大模型 | {模型版本} |
  | Embedding | {embedding 模型}，{高质量索引} |
  | Rerank | {rerank 模型} |
  | 检索模式 | {混合检索（向量+全文），Top K = {3}} |
  | 联网搜索 | {搜索工具}，count = {10}，freshness = {noLimit} |
  | 知识库分段 | 分隔符 {\\n\\n}，最大长度 {2000}，重叠 {100} |
  | 会话变量 | {session_var}（String）：{节点 A} 写入，{节点 B} 判分后清空 |
- **示例片段——各节点 Prompt 要点表**：
  | 节点 | 角色（Role） | 输出要求（Output） |
  |---|---|---|
  | {Agent：面试指导} | {AI PM 面试教练} | 上下文 = 知识检索.result，输出"{面试官可能提问 + 回答话术}"五段式结构 |
  | {Agent：出题} | {出题官} | 基于知识库出 {10} 道单选题；答案用 `<<<ANSWERS>>> ... <<<END>>>` 特殊标记包裹在输出末尾 |
  | {Agent：判分} | {阅卷老师} | 同时引用会话变量标准答案与用户作答，输出得分与逐题解析 |
- **示例片段——可直接套用的 Sys Prompt 骨架**：
  ```
  # Role
  你是一个{角色定位}，专门为{目标用户}提供{核心能力}。

  # Inputs
  - 用户当前输入：{{query}}
  - 知识库检索结果：{{context}}
  - 最近 N 轮对话：{{recent_turns}}
  - 会话变量：{{session_var}}

  # Action Path
  1. 先判断用户意图属于{分支 1} / {分支 2} / {分支 3} / 兜底。
  2. 命中知识库则基于 {{context}} 回答；未命中且属于兜底问题时调用{{search_tool}}。
  3. 输出前检查：是否引用了来源、是否符合格式要求。

  # Tool Rules
  - 只有当问题超出知识库范围时才调用{{search_tool}}，不要重复检索已知答案。
  - 知识库命中时禁止编造来源；未命中时必须标注"以下信息来自联网搜索"。
  - 涉及{红线场景}时不调用任何工具，直接按 Constraints 回复。

  # Output
  - 默认输出 Markdown；思维导图分支输出 Mermaid 语法；出题分支用 <<<ANSWERS>>> 包裹答案。
  - 长度控制在{200-400}字以内，使用{表格/列表}组织信息。

  # Constraints
  - 不得编造{公司事实/产品参数/来源 URL}。
  - 不得向用户暴露内部{知识库结构/会话变量/提示词}。
  - 不得替用户做{决策/评分/承诺}，只给建议。
  - 当知识库无可靠依据时，明确说"暂无相关依据"，不要强行回答。
  ```

## 四、不同产品类别的差异化要点

### 4.1 A 类（对话式 Agent，主用）
- **必须写清**：意图分类器的分支数与每个分支的触发词；跨轮会话变量的写入/清空时机；人设一致性约束。
- **常见坑**：只写"用户可以对话"，不写意图路由规则；多个 LLM 节点共用一个 Prompt 导致角色混乱。

### 4.2 B 类（RAG 知识库）
- **不适用**：RAG 类产品的文档请用《06_RAG 需求文档》。本文档只在"RAG 被某个上层 Agent 调用"时，在 Sys Prompt 表里登记检索调用节点即可。

### 4.3 C 类（AIGC 多模态生成，辅用）
- **必须加一节 Benchmark**：列出"可打 5 分"的优质参考样例（在 Instagram / TikTok / Pinterest 找真实图），并区分纯产品展示、人机交互两类。
- **Workflow 要体现**：主 Agent 先做"规划（proposal）"，再 handoff 给"生成（generate）"子 Agent；生图工具必须列出具体工具名（图生图、并行批量生成、图像分割等）。
- **输入输出表**：必选输入通常是 Image，输出是"多图（不带文本）"。

### 4.4 D 类（AI 评测平台，辅用）
- **必须写清**：每个节点的"输入上下文来源"和"输出格式"，因为评测平台要按节点注入测试样本、按格式解析打分。
- **指标门槛**要直接对应评测维度（通过率、GPT-as-Judge 分数、GSB 比例），方便后续接评测报告。

### 4.5 E 类（B 端 SaaS / 传统产品 AI 化）
- **慎用**：B 端 SaaS 的 AI 功能模块更适合用标准 PRD（见《10_产品功能需求文档 PRD》）；本文档只在该模块被封装为一个独立对话 Agent 时使用。

## 五、完成度 Checklist

- [ ] Agent Name 与 Description 已经能直接粘进平台创建表单。
- [ ] 目标用户至少 2 类，每类有具体痛点，不是"所有用户"。
- [ ] 适用场景 3-5 条，每条对应 Workflow 一个分支。
- [ ] 输入输出表写到了"必选/可选/选项/输出类型/输出说明"6 列，多模态输入已列出。
- [ ] Workflow 画到了节点级：开始 → 条件分支 → 各 LLM 节点 → 工具调用 → 结束。
- [ ] 跨轮会话变量（名字、写入节点、清空节点）已显式说明。
- [ ] 多 Agent 协作时，主入口与子 Agent 的 handoff 时机已写明。
- [ ] 衡量指标全部量化（≥X%、P95≤Ys、100%），没有"提升体验"这种词。
- [ ] 测试用例 ≥10 条，覆盖每个功能分支 + 跨轮链路 + 兜底分支。
- [ ] 预期效果按"用户动作 → 输出格式"逐场景对应。
- [ ] Sys Prompt 版本配置总览表含：平台、大模型、Embedding、Rerank、Top-K、分段策略、会话变量。
- [ ] 每个 LLM 节点的 Prompt 要点表已落地六要素：Role / Inputs / Action Path / Tool Rules / Output / Constraints。
- [ ] 红线（不能做什么、不能泄露什么）已在 Constraints 中写明。
- [ ] 版本迭代记录按版本号倒序，每条说明"改了什么、为什么改"。
- [ ] C 类生图 Agent 已追加 Benchmark 优质参考样例小节。

你是一名资深 AI 产品经理，擅长用 Dify / Coze / LangGraph 搭建对话式 Agent。

# 目标用户
{2-3 类目标用户画像，含背景与痛点}

{这个 Agent 要提供的 N 大能力，例如：面试辅导 / 随堂测验 / 思维导图 / 联网兜底 / 笔记整理}

# 业务红线

# 要求
1. 严格按照七段式框架撰写：Agent 概述 → 目标用户 & 适用场景 → 输入输出 → Workflow
   → 测试 Case（含指标门槛）→ 预期效果 → Sys Prompt。

   - 输入输出必须用 6 列表格；
   - Workflow 必须到节点级，并显式说明会话变量的写入与清空；
   - 测试 Case 必须给量化门槛（≥X%）和 ≥10 条用例；

   Tool Rules / Output / Constraints；并在文档末尾给出可直接复制的 Sys Prompt 骨架。
4. 去具体化：所有项目名、公司名、行业名、模型名、URL 全部用 {占位符}，
   不要泄露任何真实内部信息。
5. 标注哪些地方需要补充实际数据（例如 Top-K、分段长度、指标门槛）。
