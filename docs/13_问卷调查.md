# 【问卷调查】SKILL

> **适用产品类别**：A / B / C / D / E 全类别。问卷是 AI 产品从"定性访谈"走向"定量判断"的桥梁——A 类对话式 Agent 要靠它测"多轮对话坚持度、角色沉浸感、主动触发接受度"；B 类 RAG 要靠它测"引用溯源信任度、拒答接受度、知识库覆盖满意度"；C 类 AIGC 要靠它测"生成结果采纳率、修改成本感知、风格偏好"；D 类评测平台要靠它测"评分一致性感知、bad case 修复满意度"；E 类 B 端 SaaS 要靠它测"商户使用频率、付费意愿价格点、与现有系统集成满意度"。访谈告诉你"为什么"，问卷告诉你"多少人、多大比例"。
> **文档目的**：把一次量化调研从"想知道什么"变成"一张能直接投放的问卷 + 一套回收后能跑的分析方案"，让 PM 拿着这份文档就能去问卷星/腾讯问卷搭表、投放、清洗、出结论。读者是 PM、用研、运营、数据分析师。
> **撰写时机**：定性访谈已经跑过一轮、用户画像初稿已完成、需要"量化验证"或"回答一个具体决策问题"的时候。典型时机：①立项前的需求探索；②MVP 上线后的满意度追踪；③定价前的付费意愿测试；④流失归因；⑤概念测试（新功能方向选 A 还是 B）。

---

## 〇、先选问卷类型：5 种典型问卷写法不要混着用

写问卷之前先回答一个问题：**这次问卷要支撑什么决策？** 不同决策对应不同问卷结构，不要一份问卷想测所有东西。

| 问卷类型 | 要回答的问题 | 典型场景 | 主结构重点 | 样本量建议 |
|---|---|---|---|---|
| **满意度追踪** | "用得怎么样？哪里不满意？" | 版本上线后、季度 NPS 追踪 | CSAT/NPS/HEART 矩阵为主，AI 专项模块 | 300-500 份 |
| **需求探索** | "用户现在怎么做这件事？痛点多大？" | 0→1 立项前、新方向探索 | 行为题先于态度题，痛点排序，任务耗时 | 385+ 份（Cochran） |
| **付费意愿** | "愿意付多少钱？什么触发付费？" | 定价、付费版设计 | Van Westendorp 价格敏感度 + 付费触发点 | 300-500 份 |
| **概念测试** | "A 方案 vs B 方案哪个更想买？" | 新功能方向选 A/B/C | 概念描述卡片 + 购买意愿 + 偏好排序 | 200-400 份 |
| **流失归因** | "为什么不用了？哪里流失的？" | 沉默用户/卸载用户回访 | 流失节点定位 + 回归可能性 | 100-200 份（流失用户本来就少） |

**裁剪规则**：
- 一份问卷只测一个主目标，副目标不超过 2 个。想测满意度又想测付费意愿，拆成两份。
- 问卷总题量控制在 15-25 题，完成时长 ≤5-7 分钟。超过 10 分钟，中途放弃率飙升。
- 问卷类型决定了筛选题、模块顺序、分析方法——先选类型，再搭模块。

## 一、撰写前需要收集的资料清单

### 1.1 调研目标与决策信息
- 这次问卷要回答的核心业务问题（一句话，例如"用户愿意为'AI 不用于训练'付多少钱"）
- 结果支撑什么决策（功能优先级 / 定价 / 改版 / 投放 / 概念选 A 还是 B）
- 决策时间点（问卷回收后多久要出结论）
- 预算与可投放样本渠道（自有用户池 / 问卷星样本 / 社群投放 / 客服回访）

### 1.2 受访者定义
- 目标人群画像（年龄/职业/行业/使用频率/付费状态）
- 排除条件（例如"最近 3 个月没填过同类问卷的人"、"内部员工及其家属"）
- 抽样方式（随机抽样 / 配额抽样 / 便利抽样 / 拦截抽样）
- 配额要求（例如"新用户 vs 老用户 = 4:6"、"免费 vs 付费 = 7:3"）

### 1.3 已有素材
- 定性访谈中发现的高频痛点/期待原话（用作问卷选项归纳来源）
- 后台行为数据（使用频率、留存、功能渗透——用来交叉验证问卷自报告）
- 客服工单/应用商店评论（用户原话，用作开放题选项）
- 上一次问卷结果（如果有，看哪些题要继续追踪）

### 1.4 问卷平台与技术约束
- 用什么平台搭（问卷星 / 腾讯问卷 / 金数据 / Qualtrics / Typeform）
- 是否需要逻辑跳转（skip logic）
- 是否需要移动端适配（大多数 C 端问卷在手机上填）
- 激励方式（红包 / 抽奖 / 礼品 / 无激励）

## 二、资料来源渠道

| 来源 | 拿什么 |
|---|---|
| 定性访谈逐字稿 | 痛点原话、期待原话，用作封闭题选项归纳 |
| 后台埋点数据 | 真实使用频率、漏斗、留存——用来交叉验证问卷自报告 |
| 客服工单/应用商店评论 | 高频抱怨关键词、流失原因线索 |
| 上一次问卷数据 | 纵向对比基线 |
| 问卷平台样本服务 | 当自有用户池不够时的补充样本（注意代表性偏差） |
| 行业公开报告 | 同类产品的用户分布基准（用来校准样本结构） |
| Pew/SurveyMonkey/HEART/SHS 等方法论 | 题目措辞、量表设计、信效度检验方法 |

> **铁律**：问卷选项不是 PM 拍脑袋写的——每个封闭题的选项都要能指回访谈原话或工单原文；写不出来源的选项，要么删掉，要么改成开放题。

## 三、完整框架结构（到三级标题）

> 以下章节按"一份完整问卷从开篇到致谢页"的顺序排列。A/B/C/D/E 各类按"差异化要点"章节裁剪；但 **第 0、1、2、3、4、5、7、8、9 章是任何问卷都不能省的**。

### 3.0 问卷元信息与设计说明

- **这一节写什么**：开篇一页纸讲清"这是哪份问卷、测什么、样本多少、用什么分析方法"。这份文档不是给用户看的——是给 PM 自己和决策者看的，让以后回看时知道"这份问卷当时要回答什么问题"。
- **颗粒度要求**：至少 8 个字段——问卷名称、版本号、问卷类型（5 选 1）、核心决策问题、目标样本量、实际回收量、有效样本量、投放渠道、投放时间、主分析方法。
- **填写要点**：
  - **问卷类型必须先选**（见第〇章决策表）——不要写完才发现结构不对。
  - 目标样本量给计算依据（Cochran 公式，见 3.10），不要拍脑袋。
  - 显式写"哪些题是必测、哪些题是探索性"——探索性题的结论要打折。
- **示例片段**：
  ```
  | 字段 | 内容 |
  |---|---|
  | 问卷名称 | {产品名} {YYYY 年 Q{X}} 用户满意度与付费意愿调研 |
  | 版本号 | v1.0 |
  | 问卷类型 | 满意度追踪（主） + 付费意愿测试（副） |
  | 核心决策问题 | ①当前 CSAT/NPS 多少、哪里最不满意；
  ②用户愿意为"{高级功能}"付多少月费 |
  | 目标样本量 | 385 份（95% 置信、±5% 误差，Cochran 公式） |
  | 实际回收 / 有效 | {实际回收 N} 份 / {有效 N} 份（清洗后） |
  | 投放渠道 | ①产品内弹窗（活跃用户）；②问卷星样本（补充沉默用户） |
  | 投放时间 | {YYYY-MM-DD} 至 {YYYY-MM-DD}，共 {N} 天 |
  | 主分析方法 | 描述统计 + 交叉分析（按使用频率/付费状态分层）
  + Van Westendorp 价格敏感度 + Cronbach's α 信度检验 |
  | 必测题 | CSAT、NPS、AI 幻觉容忍度、付费意愿价格点 |
  | 探索性题 | 对"主动触发功能"的接受度（首次测，结论供参考） |
  ```

### 3.1 调研说明与 Consent（开篇页）

- **这一节写什么**：用户点开问卷看到的第一屏。必须在 30 秒内让用户知道"这是什么、要多久、会不会骚扰我、为什么要填"。
- **颗粒度要求**：至少 4 件事——背景与目的（一句话）、预计用时（≤5-7 分钟）、匿名承诺与数据用途、隐私与自愿填写声明。
- **填写要点**：
  - **不要写"为了提升用户体验"这种废话**——具体说"我们想了解你对{最近版本}的看法，用来决定下个版本先改什么"。
  - 预计用时要诚实——写"约 5 分钟"就真的是 5 分钟，写 5 分钟但要 15 分钟，中途放弃率会翻倍。
  - 匿名承诺要写清"不收集手机号/身份证/精确位置"——这是 AI 产品尤其敏感的一条。
  - 自愿填写声明要写"你可以随时退出，不会影响你使用产品"。
- **示例片段**：
  ```
  【调研说明】

  你好，我们是{产品名}团队。

  这是一份关于{你最近使用{产品名}的体验}的简短调研，大约需要 {5} 分钟。
  你的回答将直接用于我们决定{下个版本优先改进哪些功能}。

  · 本问卷完全匿名，我们不会收集你的手机号、身份证号或精确位置；
  · 你的回答只用于产品改进，不会用于任何营销推送；
  · 你可以随时退出，不会影响你继续使用{产品名}；
  · 完成问卷后可参与{抽奖/领取红包}，详情见最后一页。

  点击"开始"即表示你已了解上述说明并自愿参与。
  ```

### 3.2 筛选题（Screener）

- **这一节写什么**：放在最前面的 3-5 道题，用来过滤"不符合目标人群"的人。不符合的直接终止（感谢页），不要浪费后面的题。
- **颗粒度要求**：3-5 题；每题写清"题目、选项、逻辑跳转（不符合跳到哪）、配额作用"；至少 1 道配额题（年龄/城市/职业）。
- **填写要点**：
  - **筛选题要短**——不要把人口学问题都放前面，筛选题只问"是不是目标人"。
  - 最关键的筛选题放第一题（例如"你最近 3 个月用过{产品名}吗？"——没用过的直接走"潜在用户"分支或终止）。
  - 配额题要写清配额比例——例如"25-30 岁至少 30%"，事后用来校准样本结构。
  - **逻辑跳转要显式画出来**：谁跳、跳到哪、终止还是走另一支。
- **示例片段**：
  ```
  S1. 你最近 3 个月使用过{产品名}吗？（单选，必填）
      ○ 是 → 继续 S2
      ○ 否 → 跳到"潜在用户模块"（3.2.1），或终止（视调研目标）
      ○ 听说过但没用过 → 跳到"潜在用户模块"

  S2. 你使用{产品名}的频率是？（单选，必填）
      ○ 每天多次
      ○ 每天 1 次
      ○ 每周数次
      ○ 每月数次
      ○ 仅试过 1-2 次
      （注：本项目标人群为"每月至少使用 1 次"，最后 1 选项走"轻度用户"分支）

  S3. 你的职业身份是？（单选，必填）【配额题】
      ○ {学生} ○ {职场人} ○ {自由职业} ○ {其他}
      配额：职场人 ≥60%

  S4. 你的年龄段是？（单选，必填）【配额题】
      ○ 18-24 ○ 25-30 ○ 31-40 ○ 41-50 ○ 50+
      配额：25-40 岁 ≥60%

  S5. 你所在的城市层级是？（单选，必填）【配额题】
      ○ 一线 ○ 新一线 ○ 二线 ○ 三线及以下
  ```

### 3.3 使用行为模块

- **这一节写什么**：先问"你做了什么"，再问"你觉得怎么样"——行为题永远先于态度题。这是问卷设计的铁律之一：先让用户回忆行为，态度才真实；先问态度，用户会顺着态度编行为。
- **颗粒度要求**：5-8 题；覆盖"主要任务、使用频率、单次时长、使用设备、主要场景、竞品使用、与竞品对比"；行为题选项要互斥穷尽。
- **填写要点**：
  - **行为题先于态度题**——CSAT/NPS 这种态度题不要放在行为题之前。
  - 主要任务题用多选但限制 ≤3 项——"最常做的 3 件事"比"所有做过的事"更有分析价值。
  - 竞品使用题要列具体产品名（用{占位符}），不要只写"其他 AI 产品"。
  - "本产品相比竞品"题用 5 点量表（明显更好→明显更差），不要开放式。
- **示例片段**：
  ```
  B1. 你最常使用{产品名}完成哪些任务？（多选，最多选 3 项，必填）
      □ {写作/文案生成}  □ {问答/查资料}  □ {编程}
      □ {翻译}  □ {总结长文}  □ {绘图/图片生成}
      □ {学习/备考}  □ {客服/售后}  □ {其他：____}

  B2. 你平均每次使用{产品名}多长时间？（单选，必填）
      ○ 5 分钟以内  ○ 5-15 分钟  ○ 15-30 分钟  ○ 30-60 分钟  ○ 1 小时以上

  B3. 你主要在什么设备上使用？（单选，必填）
      ○ 手机 App  ○ 手机浏览器  ○ 电脑网页  ○ 电脑客户端  ○ 平板

  B4. 你主要在什么场景下使用？（多选，必填）
      □ 工作  □ 学习  □ 娱乐/闲聊  □ 生活琐事  □ 其他：____

  B5. 除了{产品名}，你还用过哪些同类 AI 产品？（多选，必填）
      □ {竞品 A}  □ {竞品 B}  □ {竞品 C}  □ {竞品 D}
      □ 没用过其他  □ 其他：____

  B6. 相比你用过的其他 AI 产品，{产品名}整体怎么样？（单选，必填）
      ○ 明显更好  ○ 略好  ○ 差不多  ○ 略差  ○ 明显更差  ○ 没用过其他
  ```

### 3.4 满意度与评价模块（CSAT / NPS / HEART 矩阵）

- **这一节写什么**：态度题的核心。整体满意度（CSAT）、推荐意愿（NPS）、各维度满意度矩阵。参考 HEART 框架（Happiness/Engagement/Adoption/Retention/Task Success）。
- **颗粒度要求**：至少 3 类题——CSAT 整体满意度（5 点 Likert）、NPS 推荐意愿（0-10 分 + 开放追问）、维度满意度矩阵（≤8 行，每行 5 点）。
- **填写要点**：
  - **量表方向一致**——所有 5 点 Likert 都用"1=非常不满意，5=非常满意"，不要有的正向有的反向。反向题（测敷衍）要单独标注，分析时反向计分。
  - **矩阵题行数 ≤8**——超过 8 行用户会直线作答（所有题都打 3 分）。
  - NPS 开放追问必加——"你给这个分数的主要原因是什么？"——NPS 数字本身没用，原因才有用。
  - HEART 五维不是都要测——Happiness（满意度）和 Task Success（任务完成）是必测，Engagement/Adoption/Retention 用后台数据看，不要在问卷里问。
- **示例片段**：
  ```
  C1. 【CSAT】总体来说，你对{产品名}最近一次使用体验的满意度是？
      （单选，必填，5 点 Likert）
      ○ 1 非常不满意  ○ 2 不满意  ○ 3 一般  ○ 4 满意  ○ 5 非常满意

  C2. 【维度满意度】请对以下各项打分（每行单选，必填，5 点 Likert）：
      | 维度 | 1 非常不满意 | 2 | 3 | 4 | 5 非常满意 | 不适用 |
      |---|---|---|---|---|---|---|
      | 生成内容的准确性 | ○ | ○ | ○ | ○ | ○ | ○ |
      | 生成内容的有用性 | ○ | ○ | ○ | ○ | ○ | ○ |
      | 响应速度 | ○ | ○ | ○ | ○ | ○ | ○ |
      | 多轮对话上下文连贯性 | ○ | ○ | ○ | ○ | ○ | ○ |
      | 界面与交互易用性 | ○ | ○ | ○ | ○ | ○ | ○ |
      | 引用来源的可靠性（如适用） | ○ | ○ | ○ | ○ | ○ | ○ |

  C3. 【NPS】你有多大可能把{产品名}推荐给朋友或同事？（0-10 分，必填）
      0 完全不可能 ──── 5 中性 ──── 10 非常可能
      （0-6 为贬损者、7-8 为被动者、9-10 为推荐者）

  C4. 【NPS 追问】你给出这个分数的主要原因是？（开放题，选填）
      ____________________________________________
  ```

### 3.5 AI 产品专项模块（差异化重点）

> 这一章是 AI 产品问卷区别于传统产品问卷的核心。A/B/C/D/E 各类按"差异化要点"裁剪，但 **幻觉容忍度、失败类型排序、隐私顾虑、信任建立要素** 这 4 块是任何 AI 产品都必测的。

#### 3.5.1 幻觉容忍度与出错场景矩阵

- **这一节写什么**：用户遇到 AI 编造事实时的反应，以及不同场景下用户能接受多大错误。这是 AI 产品"信任阈值"的核心测量。
- **颗粒度要求**：至少 2 题——①遇到 AI 编造时的反应（多选）；②各场景可接受出错程度矩阵（医疗/法律/财务/学习/娱乐/创意，每行 4 档）。
- **填写要点**：
  - **"遇到 AI 编造时你通常会怎么做"** 这题的选项要覆盖：自己另查 / 直接弃用 / 换个问法 / 无所谓 / 怪自己没问清——这 5 类反应决定了产品要不要做"引用溯源"。
  - 场景矩阵的 4 档建议：完全不能错 / 偶发小错可接受 / 小错无所谓 / 只要有意思——这个梯度能直接告诉你"哪些场景 AI 可以放开做、哪些场景必须人复核"。
- **示例片段**：
  ```
  D1. 当你发现{产品名}给出的信息有错误或编造了不存在的内容时，
      你通常会怎么做？（多选，最多 3 项，必填）
      □ 自己另外查资料核实
      □ 直接弃用，不再用它做这类事
      □ 换个问法再试一次
      □ 无所谓，重要的事我本来就不会全信它
      □ 怪自己没问清楚
      □ 在反馈渠道投诉
      □ 其他：____

  D2. 在以下场景中，你能接受{产品名}出错的程度是？（每行单选，必填）
      | 场景 | 完全不能错 | 偶发小错可接受 | 小错无所谓 | 只要有意思就行 |
      |---|---|---|---|---|
      | 医疗/健康建议 | ○ | ○ | ○ | ○ |
      | 法律/合规咨询 | ○ | ○ | ○ | ○ |
      | 财务/税务计算 | ○ | ○ | ○ | ○ |
      | 学习/考试辅助 | ○ | ○ | ○ | ○ |
      | 工作/职场文书 | ○ | ○ | ○ | ○ |
      | 娱乐/闲聊 | ○ | ○ | ○ | ○ |
      | 创意写作/头脑风暴 | ○ | ○ | ○ | ○ |
  ```

#### 3.5.2 失败类型排序

- **这一节写什么**：AI 产品的失败类型比传统产品多得多——幻觉、答非所问、格式错乱、误拒、太慢、偏见。要让用户排序，知道哪种失败最伤信任。
- **颗粒度要求**：1 道拖拽排序题，6 个选项；分析时看"排名第 1 的失败类型"和"平均排名"。
- **填写要点**：
  - **排序题比多选题信息量大**——多选题只能知道"哪些讨厌"，排序题能知道"最讨厌哪个"。
  - 选项要覆盖 6 类典型失败：编造事实 / 答非所问 / 格式错乱 / 不该拒绝时拒绝我 / 太慢 / 输出带偏见。
  - 如果平台不支持拖拽排序，退化为"选最不能接受的 3 项并排序"。
- **示例片段**：
  ```
  D3. 以下哪种情况最让你不想再用{产品名}？
      请按"最不能接受 → 最无所谓"排序（拖拽，必填）
      □ 编造不存在的事实或引用
      □ 答非所问、没听懂我的问题
      □ 输出格式错乱（JSON/排版乱）
      □ 不该拒绝的时候拒绝我（"我无法回答这个"）
      □ 响应太慢（等很久才出结果）
      □ 输出带偏见或不当内容
  ```

#### 3.5.3 隐私顾虑与数据使用

- **这一节写什么**：AI 产品最敏感的一题——用户是否担心对话被用于训练。这直接决定产品要不要做"不用于训练"的付费版。
- **颗粒度要求**：至少 3 题——①对"对话被用于训练"的担心程度（5 点同意度）；②愿意分享的信息类型（多选）；③为"不用于训练"付费的意愿（单选）。
- **填写要点**：
  - **隐私题放在行为题后、人口学前**——不要放最前面，会吓退用户。
  - "愿意分享的信息类型"要分梯度：匿名常识 / 工作想法 / 个人经历 / 收入财务 / 病历 / 身份证号——这个梯度能直接画出"用户愿意给多少"。
  - "不用于训练付费版"这题的答案是定价依据——30% 以上愿意付费才值得做。
- **示例片段**：
  ```
  D4. 你是否担心你在{产品名}中的对话被用于模型训练？
      （5 点同意度，单选，必填）
      ○ 1 完全不担心  ○ 2 不太担心  ○ 3 一般  ○ 4 比较担心  ○ 5 非常担心

  D5. 你愿意和{产品名}分享以下哪些信息？（多选，必填）
      □ 匿名常识性问题
      □ 工作想法/项目思路
      □ 个人经历/感受
      □ 收入/财务信息
      □ 病历/健康数据
      □ 身份证号/手机号等敏感信息
      □ 都不愿意分享

  D6. 如果{产品名}推出"对话不用于训练"的付费版，你的意愿是？
      （单选，必填）
      ○ 愿意付费，价格合适就买
      ○ 看价格再说
      ○ 不愿意，免费够用
      ○ 不愿意，我不相信"不用于训练"的承诺
  ```

#### 3.5.4 信任建立要素

- **这一节写什么**：用户在什么情况下会更信任 AI 的回答。这决定产品要不要做"引用来源、标注 AI 生成、人工复核"这些功能。
- **颗粒度要求**：1 道矩阵题，4-6 个信任要素，5 点同意度。
- **填写要点**：
  - 信任要素建议覆盖：引用来源可点击 / 标注"AI 生成" / 人工复核标识 / 历史版本对比 / 置信度提示 / "不确定时说不知道"。
  - 这题的结果直接决定"引用溯源"功能的优先级——如果 80% 用户觉得"引用来源"重要，那就是 P0。
- **示例片段**：
  ```
  D7. 以下哪些做法会让你更信任{产品名}的回答？
      （每行单选，5 点同意度，必填）
      | 做法 | 1 完全不重要 | 2 | 3 | 4 | 5 非常重要 |
      |---|---|---|---|---|---|
      | 回答附带可点击的引用来源 | ○ | ○ | ○ | ○ | ○ |
      | 明确标注"此内容由 AI 生成" | ○ | ○ | ○ | ○ | ○ |
      | 高风险内容有"人工已复核"标识 | ○ | ○ | ○ | ○ | ○ |
      | 不确定时直接说"我不知道"而非编造 | ○ | ○ | ○ | ○ | ○ |
      | 给出置信度（例如"此回答可信度 80%"） | ○ | ○ | ○ | ○ | ○ |
      | 提供历史版本对比 | ○ | ○ | ○ | ○ | ○ |
  ```

### 3.6 付费意愿模块

- **这一节写什么**：用户当前付费状态、可接受价格区间、付费触发点、不愿付费原因。如果问卷类型是"付费意愿测试"，这一章是主章节。
- **颗粒度要求**：至少 4 题——①当前付费状态；②合理月费区间（Van Westendorp 四档价格敏感度必做）；③什么让你愿意付费（多选）；④什么让你不愿付费（多选）。
- **填写要点**：
  - **Van Westendorp 价格敏感度法**是付费意愿问卷的黄金标准——问 4 个价格点：太便宜不敢买 / 便宜划算 / 偏贵但还能接受 / 太贵不买。画出来就是"可接受价格区间"。
  - 付费触发点选项要具体——"更长上下文 / 更高质量 / 去广告 / 数据隐私 / 优先响应 / 更多功能"——不要写"更好用"。
  - 不愿付费的原因要覆盖：免费够用 / 太贵 / 不信任质量 / 有替代品 / 其他。
- **示例片段**：
  ```
  P1. 你目前在{产品名}的付费状态是？（单选，必填）
      ○ 完全免费用户
      ○ 已订阅付费版
      ○ 曾订阅但已取消
      ○ 从未考虑过付费

  P2. 【Van Westendorp】关于{高级功能}的月费，以下价格点你怎么看？
      （4 道价格题，每题单选必填）
      P2a. 什么价格你会觉得"太便宜，反而怀疑质量"？____ 元/月
      P2b. 什么价格你会觉得"便宜划算，值得买"？____ 元/月
      P2c. 什么价格你会觉得"偏贵，但还能接受"？____ 元/月
      P2d. 什么价格你会觉得"太贵，肯定不买"？____ 元/月
      （分析：P2a 累计曲线与 P2d 累计曲线交点 = 最优价格点；
      P2b 与 P2c 交点 = 可接受价格区间上下限）

  P3. 什么会让你愿意为{产品名}付费？（多选，最多 3 项，必填）
      □ 更长的上下文窗口
      □ 更高质量/更准确的回答
      □ 去广告
      □ 数据不用于训练
      □ 优先响应/更快速度
      □ 更多高级功能（如{具体功能}）
      □ 其他：____

  P4. 什么让你不愿意付费？（多选，必填）
      □ 免费版已经够用
      □ 价格太贵
      □ 不信任质量，怕付了钱还是不准
      □ 有其他免费/更便宜的替代品
      □ 其他：____
  ```

### 3.7 开放反馈模块

- **这一节写什么**：封闭题测不到的东西，靠开放题捞。但开放题不要多——2 道足够，多了没人写。
- **颗粒度要求**：2 道开放题——①最希望改进的一点；②一句话描述你眼中的{产品名}。
- **填写要点**：
  - 开放题要选填——必填会让用户乱填。
  - "最希望改进的一点"比"有什么建议"好——前者逼用户聚焦，后者得到一堆废话。
  - 回收后开放题要做主题聚类（可以用 LLM 先预标，再人工合并）。
- **示例片段**：
  ```
  O1. 如果只能改进{产品名}的一件事，你希望是什么？（选填）
      ____________________________________________

  O2. 用一句话描述你眼中的{产品名}：（选填）
      ____________________________________________
  ```

### 3.8 人口学收尾

- **这一节写什么**：放在问卷最后（不要放前面，会吓到用户）。用来做交叉分析的人口学变量。
- **颗粒度要求**：4-6 题——性别 / 年龄（如果筛选题没问）/ 学历 / 月收入 / 是否愿意接受深访（独立同意项）。
- **填写要点**：
  - **人口学放最后**——前面已经问完核心题，用户已经投入沉没成本，这时候问人口学放弃率低。
  - 收入题给区间，不要问具体数字。
  - "是否愿意接受深访"必须是独立同意项——不能默认同意，要勾选"我愿意"并留联系方式。
- **示例片段**：
  ```
  D8. 你的性别？（单选，必填）
      ○ 男  ○ 女  ○ 不愿透露

  D9. 你的学历？（单选，必填）
      ○ 高中及以下  ○ 大专  ○ 本科  ○ 硕士及以上

  D10. 你的月收入区间？（单选，必填）
      ○ 5K 以下  ○ 5K-10K  ○ 10K-20K  ○ 20K-30K  ○ 30K+  ○ 不愿透露

  D11. 是否愿意接受我们 15 分钟的电话深访（抽 {50} 元话费）？
      （单选，必填）
      ○ 愿意 → 请留下联系方式（手机号/微信）：____
      ○ 不愿意
  ```

### 3.9 致谢页

- **这一节写什么**：问卷最后一页。感谢 + 激励发放说明 + 引导。
- **颗粒度要求**：3 件事——感谢语、激励发放方式、可选的引导（关注公众号/加入反馈群）。
- **填写要点**：
  - 激励要写清"什么时候到账、怎么领"——不要只写"感谢参与"。
  - 不要在致谢页塞广告——用户已经填完了，塞广告会拉低品牌印象。
- **示例片段**：
  ```
  感谢你的参与！

  你的回答将直接帮助我们改进{产品名}。

  如果你想持续参与{产品名}的早期测试，可以加入{反馈群}（二维码见下）。
  ```

### 3.10 样本量计算、问卷设计铁律、预测试、清洗、信效度、分析方法

> 这一章不是给用户看的题——是给 PM 自己的方法论附录。写在 SKILL 里，让每次做问卷都按同一套方法来。

#### 3.10.1 样本量计算（Cochran 公式）

- **这一节写什么**：目标样本量怎么算出来的，不要拍脑袋。
- **颗粒度要求**：给出 Cochran 公式、典型参数下的样本量、有限总体校正公式。
- **填写要点**：
  - **Cochran 公式**：n₀ = z²·p(1−p) / e²
  - 95% 置信（z=1.96）、p=0.5（最保守估计）、±5% 误差（e=0.05）→ n₀ = 384.16 ≈ **385 份**
  - 如果总体较小（<10000），用有限总体校正：n = n₀ / (1 + (n₀−1)/N)
  - 实际投放要多放 20-30%——因为清洗后要剔除无效问卷。
- **示例片段**：
  ```
  | 参数 | 取值 | 说明 |
  |---|---|---|
  | 置信水平 | 95% | z = 1.96 |
  | 预期比例 p | 0.5 | 最保守估计（最大方差） |
  | 允许误差 e | ±5% | |
  | 计算样本量 n₀ | 385 份 | 1.96² × 0.5 × 0.5 / 0.05² = 384.16 |
  | 实际投放量 | 500 份 | 385 × 1.3（预留清洗损耗） |
  | 分层配额 | 新用户 40% / 老用户 60% | 每层至少 100 份才能做交叉 |
  ```

#### 3.10.2 问卷设计铁律

- **这一节写什么**：写题时必须遵守的 6 条铁律。违反任何一条，问卷数据就废了。
- **颗粒度要求**：每条铁律给"规则 + 反例 + 正例"。
- **填写要点**：
  1. **每题只问一件事**——不要"你对{产品名}的速度和准确度满意吗？"（双重 barrel）
  2. **选项互斥穷尽**——年龄区间不能重叠（25-30 / 30-35），要有"其他/不愿透露"
  3. **避免社会期许偏差**——不要问"你是否是一个负责任的用户"，要问行为
  4. **量表方向一致**——5 点 Likert 所有题同向，反向题单独标注
  5. **矩阵题行数 ≤8**——超过 8 行用户直线作答
  6. **行为题先于态度题**——先问"你做了什么"，再问"你觉得怎么样"
- **示例片段**：
  ```
  ❌ 双重 barrel：你对{产品名}的响应速度和回答准确性满意吗？
  ✅ 拆开：你对响应速度满意吗？/ 你对回答准确性满意吗？

  ❌ 选项重叠：年龄 25-30 / 30-35（30 岁的人不知道选哪个）
  ✅ 选项互斥：25-29 / 30-34

  ❌ 社会期许：你是否认真对待每次使用？
  ✅ 行为化：你最近一周使用{产品名}几次？
  ```

#### 3.10.3 预测试流程

- **这一节写什么**：问卷正式投放前，必须找 10-15 人试填，记录歧义题。
- **颗粒度要求**：预测试 4 步——试填、记录歧义、修改、再试 3-5 人确认。
- **填写要点**：
  - 预测试对象要和目标人群一致（不要找同事填——同事会"配合"你）。
  - 记录每个歧义题：哪个选项让人犹豫、哪题看不懂、哪题太长。
  - 正式投放前再试 3-5 人确认修改后的题没问题。
- **示例片段**：
  ```
  | 预测试轮次 | 人数 | 发现的问题 | 修改 |
  |---|---|---|---|
  | 第 1 轮 | 10 人 | ①D2 场景矩阵"医疗/健康"有人不确定算不算自己
  ②P2 价格题有人不知道"月费"是什么单位 ③C2 矩阵 8 行有人说太长 |
  ①加注释"包括健康类咨询" ②改为"每月订阅费（元/月）"
  ③矩阵从 8 行砍到 6 行 |
  | 第 2 轮（确认） | 5 人 | 无歧义 | 正式投放 |
  ```

#### 3.10.4 回收后清洗规则

- **这一节写什么**：回收的问卷不能直接用——先清洗。
- **颗粒度要求**：3 类剔除规则——秒答、直线作答、乱填；每类给判定标准。
- **填写要点**：
  - **秒答**：完成时长 < 理论时长的 1/3（例如理论 5 分钟，<100 秒的剔除）
  - **直线作答**：矩阵题所有行都打同一个分（例如 C2 全打 3 分）
  - **乱填**：开放题填"asdf"、"111"、"不知道"等无意义内容；人口学全选"其他"
  - 清洗后剩余样本量要 ≥ 目标样本量，否则补投放。
- **示例片段**：
  ```
  | 清洗规则 | 判定标准 | 本次剔除数量 |
  |---|---|---|
  | 秒答 | 完成时长 < 100 秒（理论 5 分钟） | {N} 份 |
  | 直线作答 | C2 矩阵 6 行全选同一分 | {N} 份 |
  | 乱填开放题 | O1/O2 填无意义内容 | {N} 份 |
  | 人口学矛盾 | 年龄选"18-24"但学历选"硕士及以上"（不必然矛盾，但复核） | {N} 份 |
  | 合计剔除 | — | {N} 份（{X}%） |
  | 最终有效样本 | — | {N} 份（≥ 目标 385） |
  ```

#### 3.10.5 信效度检验

- **这一节写什么**：量表题（CSAT/NPS/AI 专项）要检验信度和效度，否则量表数据不可信。
- **颗粒度要求**：Cronbach's α ≥0.7 可接受；KMO ≥0.6 适合做因子分析。
- **填写要点**：
  - **Cronbach's α**：衡量量表内部一致性。α ≥0.8 优秀，0.7-0.8 可接受，<0.7 说明题项设计有问题。
  - **KMO**：衡量是否适合做因子分析。KMO ≥0.7 适合，0.6-0.7 勉强，<0.6 不适合。
  - 这两个指标用 SPSS / Python（pingouin 库）一键跑。
- **示例片段**：
  ```
  | 量表 | 题项数 | Cronbach's α | KMO | 结论 |
  |---|---|---|---|---|
  | C2 维度满意度 | 6 | {0.83} | {0.78} | 信度优秀，适合因子分析 |
  | D7 信任要素 | 6 | {0.76} | {0.72} | 信度可接受 |
  | D1-D3 失败类型 | — | 排序题不做 α | — | — |
  ```

#### 3.10.6 分析方法

- **这一节写什么**：清洗完的数据怎么分析、出什么结论。
- **颗粒度要求**：至少 4 类分析——描述统计、交叉分析、因子/聚类、Logistic 回归（付费意愿）。
- **填写要点**：
  - **描述统计**：每个题的频数/百分比/均值——出图表。
  - **交叉分析**：按使用频率/付费状态/年龄分层看差异——这是最有决策价值的分析。
  - **因子分析/聚类**：把 6-8 个态度题聚成 2-3 个因子（例如"信任度因子"、"易用性因子"），看哪些因子驱动 NPS。
  - **Logistic 回归**：以"是否愿意付费"为因变量，以各态度题、人口学为自变量，找出付费的关键驱动因素。
- **示例片段**：
  ```
  | 分析方法 | 用什么 | 回答什么问题 |
  |---|---|---|
  | 描述统计 | Excel/SPSS | CSAT 多少、NPS 多少、各题百分比 |
  | 交叉分析 | 按使用频率（高/中/低）分层 | 高频用户和低频用户的满意度差异 |
  | 因子分析 | SPSS/Python | 哪 2-3 个因子驱动了 NPS |
  | Logistic 回归 | SPSS/R | 哪些因素显著影响付费意愿 |
  | Van Westendorp | 4 道价格题累计曲线 | 最优价格点在哪 |
  | 开放题主题聚类 | LLM 预标 + 人工合并 | 用户最常提到的改进点 |
  ```

## 四、不同产品类别的差异化要点

### A 类（对话式 AI / Agent 产品）
- **3.5 AI 专项加厚**：重点测"多轮对话坚持度"（平均聊几轮会停）、"角色沉浸感"（用户愿不愿意跟 AI 角色扮演）、"主动触发接受度"（AI 主动找你 vs 你主动找 AI，哪个更接受）。
- **3.4 满意度矩阵**：加一行"多轮上下文连贯性"——这是 A 类产品的生死线。
- **新增模块**：可以加一道"你希望 AI 主动找你吗"的场景题（"如果你 3 天没用，AI 发消息提醒你，你什么感受"）。
- **付费意愿**：A 类付费触发点通常是"更长记忆 / 更懂我 / 更多角色"，不是"更准确"。

### B 类（RAG 知识库 / 问答产品）
- **3.5.4 信任要素是核心**：引用来源可靠性、拒答接受度（"AI 说我不知道"用户能不能接受）是 B 类必测。
- **3.4 满意度矩阵**：加"引用来源准确性"、"知识库覆盖度"两行。
- **新增模块**：测"用户会不会自己去核实 AI 给的答案"——按场景分（医疗/法律/财务 vs 娱乐/闲聊），这个比例直接决定"引用溯源"功能的 ROI。
- **失败类型排序**：B 类要把"编造引用来源"单列——这是 B 类最伤信任的失败。

### C 类（AIGC 多模态生成产品）
- **3.3 行为模块加厚**：测"生成结果采纳率"（直接用 / 改了再用 / 完全不用）、"平均修改几轮才满意"、"最常改什么"。
- **3.4 满意度矩阵**：加"风格一致性"、"生成速度"、"修改便利性"。
- **新增模块**：风格偏好（用户喜欢什么风格——写实/插画/3D/复古）、"第一次生成满意的比例"（啊哈时刻测量）。
- **失败类型排序**：C 类要把"生成结果跑偏/不符合 prompt"单列。

### D 类（AI 评测平台 / 内部工具）
- **3.3 行为模块**：测"评测人员每周评多少题、平均每题花多久、评分一致性自评"。
- **3.4 满意度矩阵**：加"评分标准清晰度"、"bad case 反馈闭环速度"、"工具效率提升"。
- **新增模块**：测"bad case 修复满意度"（你提的 bad case 修了吗、修得对吗）、"自动评分准确率感知"（你觉得 LLM-as-Judge 打得准吗）。
- **人口学**：D 类要加"你的专业背景/从业年限"——这是评分一致性的关键变量。

### E 类（B 端 SaaS / 传统产品 AI 化）
- **3.2 筛选题**：必须区分"老板/店长/店员"——这三类人的问卷结构完全不同，最好拆成 3 套问卷。
- **3.3 行为模块**：测"商户使用频率"（每天/每周/每月）、"与现有系统集成满意度"（ERP/CRM/工单系统）。
- **3.6 付费意愿**：B 端付费意愿不能只问个人——要问"公司预算谁批、多少钱需要审批、决策周期多长"。
- **新增模块**：测"AI 建议是否被标注为建议"的接受度——B 端最敏感的是"AI 直接改正式数据"，要测"AI 给建议、人确认"这个模式的接受度。
- **样本结构**：B 端问卷要按"客户规模（大/中/小）"和"行业"配额——不同规模客户需求差异巨大。

## 五、完成度 Checklist

- [ ] 开篇已选定问卷类型（5 选 1），不是一份问卷想测所有东西
- [ ] 问卷元信息页写清了版本、核心决策问题、目标样本量、投放渠道、分析方法
- [ ] 开篇调研说明含背景/用时/匿名承诺/自愿声明，用时诚实
- [ ] 筛选题 3-5 题，含至少 1 道配额题，逻辑跳转显式画出
- [ ] 行为题先于态度题（CSAT/NPS 不在行为题之前）
- [ ] CSAT + NPS（含开放追问）+ 维度满意度矩阵（≤8 行）齐全
- [ ] AI 专项模块含：幻觉容忍度、失败类型排序、隐私顾虑、信任要素
- [ ] 付费意愿模块含 Van Westendorp 四档价格题
- [ ] 开放题 2 道，选填
- [ ] 人口学放最后，含独立深访同意项
- [ ] 样本量按 Cochran 公式计算（385 份为基线），实际投放多 20-30%
- [ ] 问卷设计铁律已自查（一题一事/选项互斥/量表方向一致/矩阵≤8 行）
- [ ] 预测试 10-15 人完成，歧义题已修改
- [ ] 清洗规则已定义（秒答/直线作答/乱填）
- [ ] 信效度检验计划已写（Cronbach's α ≥0.7 / KMO ≥0.6）
- [ ] 分析方法已写（描述/交叉/因子/Logistic/Van Westendorp）
- [ ] 差异化要点已按 A/B/C/D/E 裁剪
