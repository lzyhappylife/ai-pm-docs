# 单品竞品分析报告（深度体验报告）SKILL

> **适用产品类别**：A / B / C / D / E 全类别适用。单品深度拆解是 0→1 阶段理解"别人到底怎么做"的核心动作，任何类别都需要至少 1-2 个核心竞品的一手体验记录，而不是只靠行业报告二手信息。
> **文档目的**：对 1 个（最多 2 个）核心竞品做"亲手用、亲手拆、亲手质疑"的深度体验，输出可被自家产品 PM/研发/设计直接借鉴或规避的结论，而不是泛泛的功能罗列。读者是本团队的 PM、研发负责人、设计负责人和决策者。
> **撰写时机**：构想阶段后期（行业调研、多产品横向对比完成后），选定 1-2 个"最像我们要做的东西"的竞品做深度拆解；MVP 期间如发现关键对标产品，可补做。

---

## 〇、先选刀：方法论选择决策（动笔前必读）

单品竞品拆解有三套成熟刀法，**不要三套全上**，先根据竞品类型选一把主刀，其余作为补充章节。

| 竞品类型 | 主刀方法论 | 适用类别举例 | 什么时候选它 |
|---|---|---|---|
| **C 端对话/问答/助手类**（用户直接聊天、有清晰"一句话定位"） | **六刀定位法**（参考：{竞品A}） | A 对话式 Agent、B RAG 问答、E 带 AI 助手的 SaaS | 你想搞清楚"它到底帮谁干什么活、PM 做了哪些取舍" |
| **AIGC 生成/多 Agent 平台类**（输入→输出一条管线、多工种协作） | **8 维评测表法**（参考：{竞品B}） | C AIGC 多模态生成、A 多 Agent 平台 | 你想量化"它生成效果到底几分、卡在哪一维" |
| **垂直 Agent / 个人助理类**（能调用工具、有记忆、能自主规划） | **Agent 八维拆解法**（参考：{竞品C}） | A 个人 Agent、A 销售/面试陪练、D 评测平台 Agent | 你想看透"它的模型/记忆/工具/规划/安全是怎么搭的" |

**裁剪规则**：
- 主刀章节必须写全。
- 另外两套方法论只挑 1-2 个相关章节作为补充（例如：用六刀定位法的对话助手，可以补一节"Agent 八维中的记忆/安全"；用 8 维评测表的生成产品，可以补一节"PM 视角的一个决定"）。
- 文末"我还没搞懂的问题"是硬性章节，无论用哪把刀都必须写——这是拆解报告区别于软文的关键。

## 一、撰写前需要收集的资料清单

### 1.1 用户侧资料
- 竞品的目标用户画像（从官网文案、应用商店评论、社群发帖反推）
- 典型使用场景（3-5 个，来自官方 Demo、视频号、用户晒单）
- 用户真实评价（应用商店 1-5 星各取 5 条、小红书/即刻/Product Hunt 评论）
- 付费墙前后的体验差异（免费版能干嘛、付费版解锁什么）

### 1.2 业务侧资料
- 竞品的一句话定位（官网首屏 slogan）
- 商业模式（订阅/按量/打赏/导流抽成/广告）
- 定价档位（免费/基础/专业/企业，各档权益）
- 团队背景（创始人、融资轮次、团队规模、公开演讲）
- 增长数据（下载量、排队申请数、日活/月活公开口径、GMV 如有）

### 1.3 技术侧资料
- 产品形态（独立 App / 小程序 / 网页 / 飞书 Bot / 嵌入第三方）
- 交互入口（聊天框 / 画布 / 流程连线 / 表单 / 语音电话）
- 背后是 Chatbot / 单 Agent / 多 Agent / 固定 Workflow（从行为反推）
- 是否接 RAG、接了哪些外部工具/插件/电话/邮箱/日历
- 模型选型线索（官方发布会、备案号、技术博客、SDK 调用痕迹）

### 1.4 数据侧资料
- 一手实测记录（至少完成 3 条正向路径 + 3 条异常路径，截图/录屏留存）
- 成本线索（推理成本、订阅价格反推毛利、是否有免费额度）
- 护城河线索（专有数据、行业 know-how、独家工具接入、社区/品牌）

## 二、资料来源渠道

| 资料类型 | 推荐渠道 |
|---|---|
| 一手体验 | 亲自注册使用、录屏、多账号对比、故意喂异常输入 |
| 官方定位与商业模式 | 官网、定价页、隐私政策、应用商店介绍页 |
| 团队与融资 | 36 氪/晚点/IT 桔子、创始人播客/推特、LinkedIn、Crunchbase |
| 技术架构线索 | 技术博客、GitHub、产品发布会、备案信息、SDK 抓包 |
| 用户口碑 | 应用商店评论区、小红书、即刻、V2EX、知乎、Product Hunt、X/Twitter |
| 行业格局 | 行业报告、竞品官网"竞品对比"页、第三方测评视频 |
| 二手拆解 | 同类拆解文章（仅作线索，必须亲手验证，不能直接抄） |

> **铁律**：所有事实性结论必须标注来源类型——【页面事实】（亲眼看的）/【合理推断】（基于 X 推出）/【官方说法】（引用了哪篇文章/播客）/【未公开】（没查到，不猜）。混在一起是新手最常犯的错。

## 三、完整框架结构（到三级标题）

> 说明：以下章节按"先选刀"原则裁剪。`3.1-3.3` 是所有刀法共用的开篇，`3.4-3.6` 是三套刀法的主体，`3.7-3.9` 是所有刀法共用的收尾。

### 3.1 基础信息与拆解说明

- **这一节写什么**：竞品是谁、为什么选它、用了什么刀法、实测覆盖了哪些场景。
- **颗粒度要求**：写清竞品名称/版本/实测日期/实测账号类型；写清本次拆解用了哪把主刀、补了哪几把副刀；列出实测场景清单。
- **填写要点**：
  - 不要只写"我们拆了 {竞品名}"，要写"为什么是它而不是别家"（例如：它是赛道里第一个跑通付费的 / 它的 Prompt 工程和我们最像）。
  - 实测场景至少包含：1 条正向主路径、1 条信息不全路径、1 条危险/越界路径。
- **示例片段**：
  > 本次拆解对象：{竞品名}（{产品形态}，{版本号}，{实测日期}）。
  > 选它的原因：它是{赛道}里唯一跑通{关键商业模式}的产品，且在{关键能力}上被多家同行引用。
  > 主刀方法论：{六刀定位法 / 8 维评测表法 / Agent 八维拆解法}；补充章节：{例如 Agent 八维中的"记忆"与"安全"}。
  > 实测覆盖：正向路径 {N} 条、异常路径 {N} 条、付费墙前后对比 {是/否}。

### 3.2 一句话定位与行业地图位置

- **这一节写什么**：它到底帮谁、干什么活、靠什么收钱；在行业地图上占哪一格、旁边有谁。
- **颗粒度要求**：一句话定位不能超过 50 字；必须写出"替掉了什么"（替代的不是同类产品，而是旧习惯/旧痛点）；必须指出"主格 vs 副业"。
- **填写要点**：
  - 判断标准是"它收钱收的是哪件活"，不是"用户在哪个界面停留"。
  - "对手是谁"要写透——不是直接竞品，而是用户原本在解决这个痛点时做的事。
- **示例片段**：
  > **行业地图位置**：主格：{例如 问答与搜索}；副业：{例如 一脚踩进医疗服务导流}。
  > **一句话定位**：当{目标用户}有{具体场景}时，想要{AI 能力}帮自己{核心动作}，以便{预期结果}。
  > **替掉了什么**：{不是 X 产品，而是"人到医院脑空白"这种普遍痛点 / 翻开搜索引擎十条广告的旧习惯}。

### 3.3 关键数据与产品概览

- **这一节写什么**：用一张表把公开可查的核心数字摆出来，让读者 30 秒建立量级认知。
- **颗粒度要求**：至少 6 个数字（GMV/估值/日增/留存/团队规模/获客方式）；未公开的写"未公开"，不要猜。
- **填写要点**：
  - 每个数字必须标注口径和来源时间，否则没有参考价值。
  - 同时列出"产品构成"（前台一个输入框 + 后台几条管线，一句话讲清）和"面向谁"。
- **示例片段**：

  | 指标 | 数值 | 指标 | 数值 |
  |---|---|---|---|
  | {关键商业指标1} | {数值} | {用户增长指标} | {数值} |
  | {关键商业指标2} | {数值} | {核心留存指标} | {数值} |
  | {团队规模} | {数值} | {获客方式} | {数值/描述} |

  > **产品构成**：把{行业整套流程}抽象成前台{交互入口} + 后台{几条 Agent/Workflow 管线}。
  > **面向用户**：{PUGC/PGC/专业 B 端/C 端大众}。
  > **应用场景**：{3-5 个，列短句}。

### 3.4【主刀 A：六刀定位法主体】用户旅程与确认点

> 仅当主刀选六刀定位法时本节为必写；其他刀法可作为 3.6 的参考。

- **这一节写什么**：正向五步怎么走、异常路径怎么处理、关键"小旗"（确认点）在哪。
- **颗粒度要求**：正向路径要画成带箭头的流程图；异常路径至少实测 3 条（信息不全 / 危险信号 / 用户不满意要求重写）；每条异常路径要引用真实对话原话，不能概括。
- **填写要点**：
  - 异常路径是最有信息量的部分——它暴露了 PM 真正的取舍。
  - "确认点"是指流程中强制停下来等用户决策、或自动触发安全兜底的位置，用 🚩 标出。
  - 证据要分类标注：哪些是【页面事实】、哪些是【合理推断】。
- **示例片段**：
  > **正向五步**：{步骤1} → {步骤2} → {步骤3} → {步骤4} → {步骤5}。
  >
  > **异常 ①：信息给不全**（原话："{用户只说了几个字}"）
  > - 竞品先追问再答："{引用竞品真实回复原话}"
  > - 它记得我之前说过的"{前文信息}"，主动关联。
  > - 立刻列出{危险信号清单}，并说"{引导动作原话}"。
  >
  > **确认点（小旗位置）**：
  > ```
  > 用户输入
  >   ↓
  > 🚩 确认点1：信息够不够？（够→直接生成；不够→先追问一句）
  >   ↓
  > 🚩 确认点2：{用谁的数据/走哪条分支}
  >   ↓
  > 🚩 确认点3：{危险信号检测，自动触发}
  >   ↓
  > 🚩 确认点4：{末尾追问一句}
  > ```

### 3.5【主刀 A 续】技术层光谱与人机分工

- **这一节写什么**：它在 Chatbot / 单 Agent / 多 Agent / 固定 Workflow 光谱的哪一格；哪些事必须人来做、为什么。
- **颗粒度要求**：必须给出光谱定位结论和判断依据；人机分工表至少 3 列（任务环节 / AI 做什么 / 人做什么 / 为什么这样分）；"为什么要人"要拆出 2-3 层原因（合规、主观、成本）。
- **填写要点**：
  - 判断光谱的方法：换个说法输出结构是否变化（变→不是固定 Workflow）；有没有多角色交接界面（有→多 Agent）；是否只答一句话（是→Chatbot）。
  - "为什么要人"的三层原因是精华：第一层是合规/担责、第二层是主观偏好、第三层是成本。少写一层就少一层洞察。
- **示例片段**：
  > **光谱定位**：{Agent 倾向但不是多 Agent / 单 Agent / 多 Agent 管线 / 固定 Workflow}。
  > 判断依据：{例如：换个说法输出结构就变了，说明步骤是现拆的；全程一个人设，没有角色交接界面}。
  >
  > **人机分工表**：
  >
  > | 任务环节 | AI 做什么 | 人做什么 | 为什么这样分 |
  > |---|---|---|---|
  > | {环节1} | {动作} | {动作} | {原因} |
  > | {环节2} | {动作} | {动作} | {原因} |
  >
  > **核心发现：为什么要人？**
  > - 第一层（{合规/担责}）：{例如：错了撤不回，所以只帮你准备清单、不替你诊断}。
  > - 第二层（{主观偏好}）：{例如：轻重缓急只有用户自己知道}。
  > - 第三层（{成本/付费动作}）：{例如：替你花钱挂号这一步必须人自己点}。

### 3.6【主刀 A 续】模型层两问 + 基础层三问

- **这一节写什么**：谁在想、谁在生成？能不能换？数据从哪来、会不会越用越好？什么在烧钱、怎么收回？模型之外自己攒下了什么？
- **颗粒度要求**：每个问题必须给出"事实/推断/未公开"三档标注；"能不能换"要做替换假设（换成通用大模型会怎样、换成纯 RAG 会怎样）。
- **填写要点**：
  - 不要只写"用了 GPT-4"这种废话。要写"在医疗场景下换成通用模型会损失什么"。
  - "算法层自己攒下了什么"是护城河章节——行业 know-how、规则库、Prompt 资产。
- **示例片段**：
  > **模型层①谁在想、谁在生成？**
  > - 自然语言理解+对话生成：{自研模型/某模型}【{官方说法/合理推断}】
  > - 记忆与上下文关联：{RAG + Memory 机制}【{页面事实：它记得 X}】
  > - 安全红线检测：{规则引擎+模型双保险}【{合理推断}】
  >
  > **模型层②能不能换？换了会怎样？**
  > - 换成通用大模型：{会损失什么专业性}。
  > - 换成纯知识库 RAG：{答案会像教科书，缺什么"人话"}。
  > - 结论：{该场景下，专业性比通用智力更重要}。
  >
  > **基础层①数据**：{对话记忆 / 业务数据 / 公开语料}，结论{会越用越强 / 不会}。
  > **基础层②算力**：烧钱点{X、Y、Z}，收回方式{订阅/导流抽成/广告/打赏}。
  > **基础层③算法资产**：{行业规则库 / 结构化 Prompt / 专家沉淀的 SOP}——同一个基座模型，值钱的在上面叠的{专业层}。

### 3.7【主刀 B：8 维评测表法主体】单场景实测与能力评分

> 仅当主刀选 8 维评测表法时本节为必写。

- **这一节写什么**：挑一个最能代表竞品核心能力的场景（例如"30 秒剧情短片"），端到端走一遍，然后按 8 维打分。
- **颗粒度要求**：测试 prompt 要完整贴出（不能概括）；评估权重表必须有；8 维评测表每维都要有"维度解读 / 打分逻辑 / 满分 / 得分 / 扣分原因"；分数评级要给出段位（90+/70-89/60-69/<60）。
- **填写要点**：
  - 测试场景必须能同时压到"端到端效果 + 过程交互 + 多 Agent 协作 + 底层调度"四层。
  - 扣分原因比分数本身更重要——它指出了竞品的短板。
  - 权重之和必须 = 100%。
- **示例片段**：
  > **测试场景**：{完整贴出用户输入 prompt，例如："通过 X 对比 Y，做一个 30 秒短片，分镜一/二/三……"}
  >
  > **评估权重**：
  >
  > | 评估维度 | 建议权重 | 核心考察点 |
  > |---|---|---|
  > | 端到端效果 | {40%} | 交付成品的{观赏性/一致性/有趣度} |
  > | 交互共创层 | {20%} | 流程顺滑感、指令转化 |
  > | Agent 协作层 | {25%} | 多 Agent 信息同步、纠偏 |
  > | 基础能力层 | {15%} | 多模型调度、资产复用 |
  >
  > **8 维评测表**：
  >
  > | 能力层级 | 评测维度 | 维度解读 | 打分逻辑 | 满分 | 得分 | 扣分原因 |
  > |---|---|---|---|---|---|---|
  > | 端到端 | {成品质量} | {故事闭环、音画同步} | {是否可消费} | {20} | {13} | {X 处音色突变} |
  > | 端到端 | {视觉一致性} | {跨分镜角色稳定} | {是否角色闪烁} | {20} | {19} | — |
  > | 用户层 | {意图理解} | {大白话→专业指令} | {艺术总监转化准不准} | {15} | {14} | — |
  > | 用户层 | {反馈灵活性} | {跳出-回归机制} | {手动改后能否回主流程} | {10} | {8} | {改完后丢失上下文} |
  > | 技术层 | {多 Agent 协作} | {各 Agent 信息同步率} | {改剧本后分镜是否同步} | {15} | {14} | — |
  > | 技术层 | {行业知识库} | {专业术语运用} | {是否算法而非抽卡} | {10} | {9} | — |
  > | 模型层 | {多模型调度} | {不同场景选最优模型} | {是否按分镜特点选模型} | {5} | {5} | — |
  > | 模型层 | {资产复用} | {资产库调用} | {IP 形象能否跨镜头复用} | {5} | {5} | — |
  >
  > **总分**：{XX}/100，段位：{60-69：创意启发强、复杂细节仍有瑕疵}。

### 3.8【主刀 B 续】产品定位差异点与商业模式

- **这一节写什么**：它和同类 AIGC 产品差在哪；为什么能火；靠什么回本；护城河是什么。
- **颗粒度要求**：差异点要落到"具体做法"而非"我们更专业"；至少拆 2-3 个差异化设计（垂直只干一件事 / Agent 命名用行业角色 / 托管 vs 对话双模式）；护城河必须分清"模型层不是护城河"。
- **填写要点**：
  - 对比表中要有"我们"和"通用平台"两列，让差异看得见。
  - 变现方式要引用真实定价截图（免费/基础/专业/企业各档权益）。
- **示例片段**：
  > **独特点**：不在模型，而在{垂直领域} + {交付导向}。
  >
  > **差异点 1：垂直到只干一件事**
  > - 不做通用工作台，所有交互都围绕{行业核心对象}。
  > - 对比：{通用平台}强调全模态全场景，它把模型藏到底层、把{行业}工种知识提到最前台。
  >
  > **差异点 2：把 Agent 做成{行业}专业角色**
  > - 直接用真实工种命名：{艺术总监/编剧/分镜师/……}。
  > - 效果：低门槛（小白知道跟谁说改剧情）+ 高信任（专业者能定位问题在哪个环节）+ 可扩展（单个工种独立升级）。
  >
  > **差异点 3：托管模式 vs 对话模式**
  > - 托管：丢一句话全权跑完整流程（小白传播）。
  > - 对话：每步可插手（专业者保留控制感）。
  > - 两模式可串联：托管出初版 → 对话精修 → 托管批量衍生。
  >
  > **护城河**：{不是模型——大家都能接 API}；真正沉淀的是{行业工作流的算法化表达 + 多模型风格统一 + 简单界面承载复杂管线}。

### 3.9【主刀 B 续】Multi-Agent 管线逐个拆解

- **这一节写什么**：如果是多 Agent 产品，把每个 Agent 拆开看：它的输入契约、输出契约、可用工具、硬约束、Prompt 骨架。
- **颗粒度要求**：至少拆 2-3 个核心 Agent（主 Agent + 1-2 个下游 Agent）；每个 Agent 用统一模板：角色定义 / 输入契约 / 输出契约 / 硬约束 / 工具清单 / 典型 Prompt 片段；全局上下文 Schema 必须列出字段表。
- **填写要点**：
  - 不要只写"有编剧 Agent"，要写它读写哪些字段、严禁碰哪些字段。
  - 重点关注"字段引用完整性"——角色 ID、镜头 ID 的引用关系，这是多 Agent 不打架的关键。
  - 同时要写"它没做好的地方"：例如某个 Agent 连续两次输出相同口头确认、不调用下一步工具，以及推测原因和解决方案。
- **示例片段**：
  > **全局上下文 Schema（项目 PRD）**：
  >
  > ```yaml
  > project_meta: {project_id, version, technical_spec}
  > core_fields:  {script_summary, emotional_tone, visual_style_tags, scene_count}
  > characters[]: {char_id, name, description, main_image_uri, concept_sheet_uri}
  > storyboard[]: {shot_id, shot_description, asset_uri, actor_refs[], actor_lines[]}
  > ```
  >
  > **Agent：{主 Agent 名}**
  > - 角色：{做什么、不做什么}
  > - 输入：{user_brief / form_submission / 下游回调}
  > - 输出字段：{只写 brief_meta、visual_style_tags；严禁写剧本细节}
  > - 硬约束：{严禁跨步执行 / 风格标签必须来自 RAG 候选集 / 每次确认必须写 approval_log}
  > - 工具：{全局上下文读写 / RAG 检索 / 推表单卡片 / 调度下游 Agent / 状态回滚}
  >
  > **没做好的地方**：
  > - 现象：{用户已确认后，Agent 仍口头重复"您确定吗"而不调用下一步工具}。
  > - 推测原因：{状态已 confirmed 但工具层未幂等返回成功 / Prompt 未禁止口头确认}。
  > - 解决方案：{Prompt 加一条"即调用下一步工具，禁止口头确认" + 工具层幂等 + 连续两次相同输出时主 Agent 介入}。

### 3.10【主刀 C：Agent 八维拆解法主体】八维逐项体检

> 仅当主刀选 Agent 八维拆解法时本节为必写。每维统一格式：已实现能力 / 未公开或信息空白。

- **这一节写什么**：从模型、指令、记忆、工具、规划、容错、上下文、安全八个角度体检 Agent 产品。
- **颗粒度要求**：每维至少 3 条具体事实；已实现 vs 未来规划 vs 未公开三档必须分清；不允许把"未公开"推测成"应该是"。
- **填写要点**：
  - 这是最容易写成软文的刀法，关键在"未公开"标注——它反映了分析师的诚实度。
  - 八维之间有联动：记忆和上下文要分开写（记忆=长期偏好/历史；上下文=短期窗口管理）。
- **示例片段**：
  > **① 模型角度**
  > - 已实现：{自研混合推理管线 / 不同负载路由不同模型 / 后台任务批处理}。
  > - 未公开：{具体用了哪些基础模型、3-8x 效率提升的对比口径}。
  >
  > **② 指令角度**
  > - 已验证场景：{旅行预订 / 订阅退订 / 穿搭购物 / 电话代订 / 日程协调 / 紧急呼叫}（每场景一句话讲清端到端链路）。
  > - 设计哲学：{不是 task completer，而是围绕"信任/守护/兜底"高阶目标训练}。
  >
  > **③ 记忆角度**
  > - 已确认记忆类型：{偏好永久复用 / 银行交易 / 日历 / 邮箱 / 身体穿搭 / 位置 / 服务偏好 / 社交关系}。
  > - 数据飞轮：{用户给得越多→越懂处境→越能主动代决策}。
  > - 未公开：{记忆分层架构、压缩与遗忘策略}。
  >
  > **④ 工具角度**：{自有电话/邮箱/云端电脑/银行/日历/位置/电商/打车/Agent 间网络}。
  >
  > **⑤ 规划角度**
  > - 已观察：{端到端多步执行 / 主动式作息周期 / 后台自主运行占主导 / Agent 间协商}。
  > - 未来规划：{从单次任务到数月级长期目标 / 小型企业自主运营}。
  > - 未公开：{任务分解算法是 ReAct 还是 Plan-and-Execute}。
  >
  > **⑥ 容错与重试**
  > - 已确认：{独立验证网络 / 主动侦探系统 / 红蓝对抗 / 早期踩坑后推倒重构}。
  > - 未公开：{自动重试策略、错误率量化指标}。
  >
  > **⑦ 上下文窗口管理**
  > - 已确认：{同步/异步分离架构 / 端到端蒸馏剪枝}。
  > - 未公开：{上下文摘要、分层记忆、超长对话淘汰策略}。
  >
  > **⑧ 权限与安全边界**（这一维通常最有信息量）
  > - 第 1 层 输入防火墙：{阻断 Prompt 注入/社工诱导}。
  > - 第 2 层 独立守门人：{与主决策解耦、毫秒审计、一票否决}。
  > - 第 3 层 基础设施隔离：{沙箱 / 短期本地凭证 / 身份签名工具调用}。
  > - 第 4 层 用户主权：{按用户节奏开放权限、可一键收回}。
  > - 第 5 层 细粒度权限网：{信任权重的访问边、对方 Agent 越界时主动通知}。
  > - 第 6 层 商业模式即安全：{拒绝广告、选交易抽成，保证 Agent 代表用户利益}。

### 3.11【主刀 C 续】已实现 vs 未来规划总览表

- **这一节写什么**：把八维内容压成一张总览表，让读者一眼看清哪些是真本事、哪些是画饼。
- **颗粒度要求**：8 行 × 2 列（已实现 / 未来规划或未公开）；每行不超过 30 字。
- **填写要点**：
  - "未来规划"列里如果出现"Free for life"这种创始人个人目标，也要标注是"目标"而非"承诺"。
- **示例片段**：

  | 维度 | 已实现 | 未来规划/未公开 |
  |---|---|---|
  | 模型 | {自研管线，接近前沿} | {X 倍效率提升的基准口径未公开} |
  | 指令 | {8 类端到端任务} | {数月级长期宏观目标} |
  | 记忆 | {偏好/交易/日历/邮箱…} | {分层架构、压缩遗忘策略未公开} |
  | 工具 | {电话/邮箱/云端电脑/银行…} | {与商家双向撮合} |
  | 规划 | {端到端多步、主动作息} | {小企业自主运营} |
  | 容错 | {独立验证网、红蓝对抗} | {自动重试策略未公开} |
  | 上下文 | {同步异步分离} | {摘要/分层策略未公开} |
  | 安全 | {六层防御纵深} | {界面完全消融} |

### 3.12 PM 视角：如果我是 PM，我会改的一个决定

- **这一节写什么**：作为本团队 PM，挑一个竞品当前做得不够好的具体决策，给出你的改法。
- **颗粒度要求**：必须只挑"一个"决定（多了等于没挑）；要写清现状问题、改法、为什么这样改对；改法要具体到"第一句先给什么"这种颗粒度。
- **填写要点**：
  - 不要写"我会优化 UI"这种空话。要写"现在它不管轻重缓急都先给一大段解释，我会让它第一句先给结论"。
  - 这一节是给自家团队看的——它直接产出"我们要做的差异化"。
- **示例片段**：
  > **现状问题**：{它现在不管紧急程度，都是先给一大段解释和清单，最后才把{关键动作}放在底部}。
  >
  > **我的改法：结论先行，{风险/优先级}分层。**
  > 如果用户描述里有{紧急信号}，应该第一句就先给结论：
  > > "{你这个情况建议{直接动作}，别拖。下面是去之前可以准备的东西——}"
  >
  > 而不是先讲一大堆{背景知识}，最后才轻描淡写提一句"{严重的话去找 X}"。
  >
  > 理由：{该场景下"安全优先/效率优先"应该压过"内容完整"}。

### 3.13 我还没搞懂的问题（必写）

- **这一节写什么**：列出本次拆解中真正没搞懂、需要后续验证的问题，至少 2-4 个。
- **颗粒度要求**：每个问题要具体到"边界在哪、影响什么决策"；不要写"它未来会怎样"这种无法验证的问题。
- **填写要点**：
  - 这是拆解报告的诚意所在——它告诉决策者"哪些结论可以现在用、哪些还要再验证"。
  - 问题要能映射到自家产品的风险（例如：记忆边界不搞清楚，我们做同类产品就可能踩同样的坑）。
- **示例片段**：
  > **问题：{它的"记忆"边界到底在哪？}**
  > 没搞清楚：
  > 1. 这个记忆是存在{账号/设备}里吗？换个端登录还有吗？
  > 2. 它会记多久？{一个月}后还会主动提吗？
  > 3. 它会不会把用户{测试时瞎编的内容}当成真的，一直带着？
  > 4. 用户想删，在哪删？有没有"忘记我之前说过什么"的按钮？
  >
  > 这个问题关键在于：{该类产品的记忆既是护城河也是风险——记错了会误导后续判断}。我还没找到答案。

### 3.14 信息来源与免责声明

- **这一节写什么**：列出所有事实性结论的来源；声明哪些是第三方分析、哪些未做推测。
- **颗粒度要求**：一手播客/采访/官网/发布/应用商店评论，每条标日期；明确"标注未公开的部分未做任何推测性补充"。
- **填写要点**：
  - 不要把猜测写成事实。
- **示例片段**：
  > 本拆解基于以下公开来源，所有事实性表述均可回溯：
  > 1. {创始人播客名}（{日期}）——核心一手来源。
  > 2. {中文精编报道 / 英文摘要 / 官方融资公告 / 产品功能更新报道}。
  >
  > **免责声明**：本文为第三方产品分析，非竞品官方材料。标注"未公开"的部分为公开渠道未涉及的技术空白，未做推测性补充。所有数据为受访方披露口径。

## 四、不同产品类别的差异化要点

- **A 类（对话式 Agent）**：主刀优先选"六刀定位法"或"Agent 八维拆解法"。必写"记忆边界"和"安全兜底"两小节；重点看它有没有多轮状态、工具调用、主动触发。多 Agent 形态时补 3.9 的管线拆解。
- **B 类（RAG 知识库/问答）**：主刀优先选"六刀定位法"。必须额外拆：知识源从哪来、检索不到时怎么答、引用是否可溯源、是否有拒答边界。人机分工表里"专家审校"那一层通常是关键。
- **C 类（AIGC 多模态生成）**：主刀优先选"8 维评测表法"。必须真跑一遍 prompt 并打分；重点关注"跨镜头/跨次生成的一致性"和"多模型路由逻辑"。商业模式章节要写清订阅档位和免费额度边界。
- **D 类（AI 评测平台/内部工具）**：不常见的主刀场景。如要拆 D 类竞品，主刀选"Agent 八维拆解法"，重点放在"评测标准怎么定、Golden Set 怎么建、bad case 怎么闭环"，而不是 C 端体验。
- **E 类（B 端 SaaS AI 化）**：主刀选"六刀定位法"。必须额外拆：它嵌入在哪个业务流里、谁买单（管理员/一线员工）、AI 功能是卖点还是附赠、工单驱动的迭代节奏。

- [ ] 关键数据表至少 6 个公开数字，每个数字标注口径和时间

- [ ] 确认点（🚩）位置已标出，自动触发的兜底已单列

## 六、AI 生成 Prompt 模板

```
你是一名资深 AI 产品经理，擅长对竞品做"亲手用、亲手拆、亲手质疑"式的深度体验报告。
请根据以下项目信息，撰写一份《单品竞品分析报告（深度体验报告）》。

【背景输入】
- 我们要做的产品类别：{A 对话式 Agent / B RAG 问答 / C AIGC 生成 / D 评测平台 / E B 端 SaaS AI 化}
- 我们自己的一句话定位：{我们打算帮谁、干什么活}
- 本次拆解的竞品：{竞品名 / 产品形态 / 版本号 / 实测日期}
- 选它的原因：{为什么是它而不是别家}
- 主刀方法论：{六刀定位法 / 8 维评测表法 / Agent 八维拆解法}
- 实测已覆盖：正向路径 {N} 条、异常路径 {N} 条，关键截图/录屏已留存
- 已知事实（请直接使用，不要改写）：
  - {定位相关事实}
  - {关键数据：GMV/估值/团队/留存}
  - {实测对话原话 1：……}
  - {实测对话原话 2：……}
  - {实测对话原话 3：……}
- 已知未公开/待验证：{列表}

【撰写要求】
1. 严格按照《单品竞品分析报告 SKILL》的六段式结构输出；根据主刀方法论裁剪 3.4-3.11 章节。
2. 每个三级标题下必须包含：这一节写什么 / 颗粒度要求 / 填写要点 / 示例片段。
3. 事实结论必须标注来源类型：【页面事实】【合理推断】【官方说法】【未公开】——没有把握的一律写【未公开】，禁止编造。
4. "我还没搞懂的问题"至少 2 个，且映射到我们自家产品的风险。
5. "PM 视角：如果我是 PM 我会改的一个决定"只挑一个，写到"第一句先说什么"的颗粒度。
6. 去具体化：不要使用任何真实公司名、真实产品名、真实人名、真实行业黑话；全部用 {占位符} 替代。
7. 输出为 Markdown，章节编号与 SKILL 框架一致。
```
