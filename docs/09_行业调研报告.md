# 【行业调研报告】SKILL

> **适用产品类别**：A / B / C / D / E 全类别。这是所有 AI 产品 0→1 的第一道关——立项前必须回答"这个赛道值不值得进、Why now、切哪个口子"。A 类看 Agent 技术成熟度与陪伴/助手赛道，B 类看 RAG 技术栈与企业知识库渗透率，C 类看多模态成本曲线与版权合规，D 类看评测工具生态，E 类看 B 端 AI SaaS 采购决策链。没有这份报告就立项，等于闭眼跳伞。
> **文档目的**：把"赛道有没有肉、刀往哪砍、坑在哪、未来 30/60/90 天干什么"一次讲清。读者是立项决策者（Sponsor/老板/投资委员会）、产品负责人、业务 Owner。它是 Go/Pivot/Stop 决策的唯一事实依据，**不是给行业学会看的综述**。
> **撰写时机**：0→1 立项前（概念已经有了、但还没写 PRD、还没招齐研发）。一般花 1-2 周集中调研，写完即冻结；之后每个季度更新一次关键数字，不要每周改。

## 〇、先选范式：三种行业调研写法，别混着用

| 范式 | 你要回答的问题 | 典型场景 | 主结构 |
|---|---|---|---|
| **范式 A：从 0 到 1 新赛道** | "这个新赛道值不值得进？切哪个口子？" | A 类 Agent 助手、C 类多模态生成、新兴 D 类评测工具 | 执行摘要 → PEST → TAM/SAM/SOM → 产业链 → 竞争格局 → 技术路线 → 风险 → 30/60/90 计划 |
| **范式 B：进入既有垂直行业** | "这个行业（金融/医疗/教育/法律）能不能用 AI 重做一遍？" | E 类 B 端 SaaS AI 化、B 类行业知识库 | 行业现状与价值链 → 现有玩家怎么赚钱 → AI 能切哪几个环节 → 客户采购决策链 → 合规红线 → 切入点 |
| **范式 C：大厂已在场、找缝隙** | "通用大模型都在做，我还有没有机会？" | C 类垂直生成、D 类内部工具、A 类垂直 Agent | 通用玩家能力边界 → 他们懒得做/做不好的缝隙 → 缝隙够不够大（TAM） → 防御性来自哪（数据/工作流/合规） |

**裁剪规则**：
- 范式 A 必写 3.0–3.9 全部章节。
- 范式 B 把 3.1 PEST 加厚（尤其 P 政策合规），3.4 产业链改画"行业价值链"，3.5 竞争格局重点写现有 IT 厂商而非 AI 原生玩家。
- 范式 C 把 3.5 竞争格局改成"通用玩家能力边界表"，3.8 风险章加厚"被大厂免费化挤死"。
- **铁律**：无论哪种范式，3.0 执行摘要 + 3.7 结论与建议 + 3.9 附录数据口径，这三章不能省。

## 一、撰写前需要收集的资料清单

### 1.1 政策与合规侧（P）
- 国家层面：生成式 AI 服务管理暂行办法、算法推荐管理规定、深度合成规定、数据安全法、个保法相关条款
- 备案动态：已备案大模型数量（网信办季度公告）、备案材料与周期、备案被撤案例
- 行业监管：金融/医疗/教育/法律/汽车等垂直行业对 AI 的专门规定（如医疗 AI 三类证、教育 AI 教育移动互联网应用备案）
- 地方政策：北京/上海/深圳/杭州算力券、模型券、产业基金、数据交易所
- 国际政策：欧盟 AI Act 分级（通用/通用 with systemic risk/高风险/有限/最低风险）、美国行政令、出口管制（先进 GPU、EDA、HBM）

### 1.2 市场与经济侧（E）
- 全球 AI 市场规模（近 3 年实际 + 未来 3-5 年预测），分层拆分：基础模型层 / 基础设施层（算力、云）/ 中间件（向量库、RAG、Agent 框架）/ 应用层
- 中国生成式 AI 市场规模、头部厂商 ARR/收入
- 算力市场：GPU 出货量、智能算力 EFLOPS、国产芯片份额、电价与 PUE
- 企业渗透率：定期用 GenAI 的企业占比、企业 AI 支出拆分（基础设施/模型/应用）
- 目标垂直行业的 IT 支出、SaaS 渗透率、数字化预算

### 1.3 社会与用户侧（S）
- C 端用户规模与渗透率、年龄/职业/城市分层、付费意愿
- B 端客户画像：行业、规模、采购决策链（老板/CIO/业务部门/采购）、决策周期
- 典型用例 Top 10（写作/编程/客服/营销/搜索/办公/教育/设计/视频/法律）
- 未被满足的需求：应用商店差评、社媒吐槽、社群抱怨关键词

### 1.4 技术与供给侧（T）
- 模型能力：参数规模、上下文长度、多模态、推理/编码/数学基准（MMLU、GPQA、SWE-bench、AIME、HumanEval）
- 范式演进：DPO/RLHF、推理模型（o1/R1 类）、MoE、长上下文、Agent/工具调用、多智能体
- 开源 vs 闭源：HF 下载量、开源份额、国产开源模型表现
- 成本曲线：百万 token 推理成本季度变化、图像/视频生成成本变化
- 工程化：RAG、向量数据库、蒸馏、量化、边缘部署、MCP 协议

### 1.5 竞争与资本侧
- 海外头部：OpenAI、Anthropic、Google、Meta、xAI、Mistral、Cohere 的模型矩阵、定价、定位
- 国内头部：字节、阿里、腾讯、百度、智谱、月之暗面、MiniMax、DeepSeek、商汤、讯飞
- 垂直应用：C 端助手、编程、设计、视频、客服、营销、法律、医疗、教育
- 头部产品 MAU/留存/付费率（QuestMobile、七麦、点点）
- 近 4 季度全球 AI 融资总额、笔数、超大额融资（>1 亿美元）、独角兽名单、估值变化

### 1.6 本产品内部侧
- 立项发起人已有的假设（为什么觉得这个赛道有机会）
- 团队现有能力（模型？算法？行业资源？销售渠道？数据？）
- 可投入预算（6-12 个月能烧多少钱）
- 上线时限（融资节点/客户承诺/窗口期）

## 三、完整框架结构（到三级标题）

> 以下 10 章骨架融合自 8 份真实行业调研。**3.0 执行摘要 + 3.7 结论与建议 + 3.9 附录数据口径是任何项目都不能省的**；其余章节按范式裁剪。

### 3.0 执行摘要（1 页，决策者只看这一页）

- **这一节写什么**：一页纸讲完三个东西——①这个赛道值不值得进（一句话判断）；②三个核心判断（市场/技术/竞争各一句）；③对本产品的 3 条启示（要做什么、不做什么、先验证什么）。
- **颗粒度要求**：整节不超过 600 字。判断必须明确（"建议进入"、"建议观望"、"建议绕开"），不许写"有一定机会"。三个核心判断每个都要能在正文找到对应章节出处（如"详见 3.4 产业链"）。
- **填写要点**：
  - **执行摘要不是目录，是结论**。很多人把执行摘要写成"本文将从 PEST/产业链/竞争格局……展开"——这是废话，删掉。
  - 三个核心判断必须各有数字支撑（市场规模多少、CAGR 多少、集中度 CR5 多少），不能拍脑袋。
  - 对本产品的 3 条启示要可执行（"先做 X 场景"、"避开 Y 区域"、"必须在 Z 月前拿到备案"），不要写"加强技术投入"。
  - 决策者只看这一页就能 Go/Pivot/Stop，正文是用来回答质疑的。
- **示例片段**：
  ```
  【一句话判断】建议进入{目标赛道}，但窗口期仅 {12-18} 个月，必须以{一个具体场景}切入，不做通用平台。

  【三个核心判断】
  1. 市场判断：{目标市场} 2026 年规模约 {XXX} 亿元，CAGR {XX%}；其中{细分场景}占比 {XX%}、增速 {XX%}，是最快的一块（详见 3.2）。
  2. 技术判断：{关键技术，如 Agent / 多模态 / RAG} 已进入 Gartner 复苏期早期，{开源模型}能力已覆盖 {80%} 通用场景，但{垂直场景的精度}仍不足，这是缝隙（详见 3.6）。
  3. 竞争判断：头部 {N} 家厂商占 {XX%} 份额，但都在做通用能力，{垂直场景}无人做深；大厂免费策略会挤压 C 端，但 {B 端付费场景}受影响小（详见 3.5）。

  【对本产品的 3 条启示】
  1. 切入点：只做{一个具体场景 + 一类客户}，例如{某行业某岗位的某类文档处理}，不做开放平台。
  2. 必须避开：不碰{C 端通用聊天 / 通用模型微调}，那是大厂战场。
  3. 先验证：30 天内用{5 家种子客户 + 30 个真实工单}验证"愿意付费"这个假设，不验证就不写 PRD。
  ```

### 3.1 宏观环境分析（PEST）

- **这一节写什么**：从政策（Policy）、经济（Economy）、社会（Society）、技术（Technology）四个维度扫一遍外部环境，每个维度回答"这个环境对本产品是顺风、逆风、还是无关"。
- **颗粒度要求**：每个维度先给一句话结论（顺风/逆风/中性），再给 3-5 条关键事实。每条事实必须有来源。一张表收不下就拆成 2-3 张表。
- **填写要点**：
  - **P 政策**：不要只列法规名字，要写"对本产品的影响是什么"。例如"备案周期 2-3 个月，意味着 MVP 上线前要预留备案时间"。
  - **E 经济**：写清是谁在花钱——是企业 IT 预算、消费者付费、还是政府补贴。这三类钱的性质完全不同。
  - **S 社会**：C 端写用户画像和付费意愿，B 端写采购决策链。
  - **T 技术**：写清"技术成熟了吗"——这一条直接决定你是踩在浪上还是踩在沙滩上。
  - **常见坑**：把 PEST 写成行业新闻摘抄。每一条事实后面必须跟一句"对本产品意味着……"。
- **示例片段**（P 政策维度）：
  ```
  【P 政策：顺风，但有合规门槛】
  | 政策 | 生效时间 | 核心义务 | 对本产品影响 |
  |---|---|---|---|
  | {生成式 AI 服务管理暂行办法} | {2023.08} | 备案、内容安全、标识、投诉渠道 | 面向 C 端提供服务前必须备案，预留 2-3 个月；B 端私有化部署可豁免 |
  | {数据安全法/个保法} | {2021/2021} | 数据分级、跨境传输评估、用户授权 | 处理{客户合同/病历}等 PII 时必须走分级与授权流程 |
  | {欧盟 AI Act} | {2024 生效，2026 全面执行} | 高风险 AI 需合规评估、透明披露 | 若出海欧盟，{招聘/医疗/教育}场景被列为高风险，合规成本显著上升 |
  | {行业专门规定，如医疗 AI 三类证} | {待定} | 医疗器械注册 | 若进入{医疗辅助诊断}，需三类证，周期 2-3 年，0→1 阶段不建议碰 |
  ```
- **示例片段**（E 经济维度）：
  ```
  【E 经济：企业 IT 预算是主买单方，C 端付费意愿弱】
  - 全球企业 GenAI 支出 2026 年预计 {XXXX} 亿美元，CAGR {XX%}【IDC】。
  - 中国企业 AI 支出中，基础设施（算力/云）占 {XX%}、模型调用占 {XX%}、应用层占 {XX%}——应用层占比最低但增速最快【信通院】。
  - C 端订阅渗透率：{中国付费用户占比约 X%}，远低于美国 {XX%}【QuestMobile】。
  - 对本产品意味着：优先做 B 端付费场景，不要假设 C 端会为 AI 工具月付 30 元。
  ```

### 3.2 市场规模测算（TAM / SAM / SOM + 三档敏感性）

- **这一节写什么**：用 TAM（总可及市场）→ SAM（可服务市场）→ SOM（3 年内可获取）三层漏斗测算市场规模，并且必须做乐观/中性/悲观三档敏感性分析。
- **颗粒度要求**：每个数字必须有测算公式和假设；三档之间的差异（2-3 倍）要写清"什么情况下会变乐观/悲观"。SOM 不能写"占 SAM 的 1%"——要写到"目标客户数 × 渗透率 × 客单价"。
- **填写要点**：
  - **TAM 怎么算**：优先用自上而下（行业总支出 × AI 可替代比例），不要拍脑袋引用报告数字。
  - **SAM 怎么算**：TAM × 你能覆盖的地域 × 你能服务的客户规模 × 你能做的场景比例。
  - **SOM 怎么算**：3 年内目标客户数（从销售漏斗推）× 渗透率（第一年 5%、第二年 15%、第三年 30%）× 客单价（年费）。
  - **常见坑**：TAM 写得很大（"万亿市场"），SAM 和 SOM 不切实际。决策者最烦这种——"万亿市场和你有什么关系？"
  - **三档敏感性**：乐观 = 渗透率超预期 + 客单价超预期；悲观 = 大厂免费挤压 + 客户预算缩减。
- **示例片段**：
  ```
  【测算口径】
  - TAM：中国{目标行业}IT 支出 {XXX} 亿元/年 × {AI 可替代环节占比 XX%} = {XXX} 亿元
  - SAM：TAM × {可服务地域（全国 X%）} × {可服务客户规模（员工 100-1000 家企业 N 万家）} × {可做场景占比 XX%} = {XX} 亿元
  - SOM：3 年内目标客户 {N} 家 × 平均渗透率 {XX%} × 平均客单价 {X} 万元/年 = {X} 亿元

  【三档敏感性】
  | 档位 | 假设变化 | 第 3 年 SOM |
  |---|---|---|
  | 乐观 | 客单价上浮 30%、渗透率超预期 10pp、大厂未入场 | {X.X} 亿元 |
  | 中性 | 基准假设 | {X.X} 亿元 |
  | 悲观 | 大厂免费版切入、客户预算砍 30%、客单价降 20% | {X.X} 亿元 |

  【结论】即使悲观档，SOM 也有 {X} 亿元，足以支撑 {N} 人团队 {Y} 年运营；中性档是投资委员会的决策基准。
  ```

### 3.3 产业链图谱（上游 → 中游 → 下游）

- **这一节写什么**：画出"上游算力/芯片 → 中游模型/工具/框架 → 下游应用/场景"的产业链全景图，标出每一层的代表玩家、商业模式、毛利水平，以及本产品在哪个位置。
- **颗粒度要求**：每层至少列 3-5 家代表公司、商业模式、毛利率区间；明确写出"本产品在哪一层、和上下游的议价关系"。
- **填写要点**：
  - **上游**：芯片（NVIDIA/AMD/华为昇腾/寒武纪）、服务器、IDC、光模块、云厂商。写清供应风险（断供、涨价、国产替代成熟度）。
  - **中游**：基础大模型厂商、数据服务、开发框架（PyTorch/vLLM）、MLOps、向量数据库、Agent 框架。
  - **下游**：行业应用（金融/医疗/教育/制造/政务/电商/内容）。
  - **本产品位置**：是纯下游应用？还是要做一些中游能力（自建 RAG/自建 Agent 编排）？议价关系如何（对上游 GPU/云、对中游模型 API、对下游客户）？
  - **常见坑**：把产业链图画成公司名录，没有"利润在哪一层"的判断。要回答"谁在赚钱、谁在烧钱、谁是过路费"。
- **示例片段**：
  ```
  【产业链三层表】
  | 层级 | 环节 | 代表玩家 | 商业模式 | 毛利率 | 供应风险 |
  |---|---|---|---|---|---|
  | 上游 | AI 芯片 | {厂商 A/B/C} | 卖芯片/IP | 60-75% | 出口管制、国产替代中 |
  | 上游 | 云/IDC | {厂商 A/B} | 算力租赁 | 30-50% | 电价波动、产能紧张 |
  | 中游 | 基础大模型 | {厂商 A/B/C} | API/订阅/私有化 | 30-60%（烧钱期） | 模型迭代快、价格战 |
  | 中游 | RAG/向量库/Agent 框架 | {厂商 A/B} | 开源+商业版/云服务 | 70-85% | 开源挤压 |
  | 下游 | {本行业}应用 | {现有玩家 A/B/C} | SaaS 订阅/项目制 | 50-70% | 客户集中度、实施成本 |

  【本产品位置】
  - 本产品位于{下游应用层}，依赖{中游基础模型 API}与{向量库开源方案}。
  - 对上游：算力由云厂商提供，不囤 GPU；议价能力弱，但可多云切换。
  - 对中游：模型 API 可在 {N} 家间切换，不绑定单一供应商（避免被涨价掐死）。
  - 对下游：客户是{某行业某规模企业}，年付 {X-X} 万元，销售周期 {X-X} 个月。
  ```

### 3.4 竞争格局（波特五力 + 直接竞品矩阵 + 2×2 定位图）

- **这一节写什么**：先用波特五力扫一遍行业竞争激烈程度，再列直接竞品矩阵，最后画一张 2×2 竞争定位图，标出本产品的空位。
- **颗粒度要求**：五力每力给"强/中/弱"判断 + 一句话原因；直接竞品矩阵至少 5 家，列到"产品/公司/模型底座/核心功能/定价/目标用户/MAU/优势/短板"九列；2×2 图要描述坐标轴和空位。
- **填写要点**：
  - **现有竞争者**：数清楚有几家、CR5 多少、是否在打价格战。
  - **潜在进入者**：门槛是算力、数据、合规、销售渠道、还是品牌？门槛低就要警惕。
  - **替代品**：通用大模型（ChatGPT/豆包）算不算替代品？传统软件 + 人工算不算？
  - **上游议价**：GPU/云/模型 API 集中度？你能不能切换？
  - **下游议价**：客户集中度？切换成本高不高？
  - **直接竞品矩阵**：每格填具体数字，不填"较好/一般"。MAU 来自 QuestMobile/七麦，定价来自官网实测截图。
  - **2×2 图**：X 轴常用"通用度 ↔ 垂直深度"，Y 轴常用"轻量易用 ↔ 重型专业"。空位要写清"为什么这个位置没人做"——是不赚钱、还是没人想到、还是技术做不到。
  - **常见坑**：竞品矩阵只列海外知名产品，不列国内真实对手。决策者会问"那 {国内某厂商} 呢？"
- **示例片段**（直接竞品矩阵）：
  ```
  | 产品 | 公司 | 模型底座 | 核心功能 | 定价 | 目标用户 | MAU（近 30 天） | 优势 | 短板 |
  |---|---|---|---|---|---|---|---|---|
  | {竞品 A} | {公司} | {自研/第三方} | {功能 1/2/3} | {免费额度+订阅 X 元/月} | {人群} | {XXX} 万 | {优势} | {短板} |
  | {竞品 B} | {公司} | {自研} | {功能} | {企业版 X 万/年} | {行业} | {XXX} | {优势} | {短板} |
  | {竞品 C} | {公司} | {开源微调} | {功能} | {开源免费} | {开发者} | N/A（开源） | {优势} | {短板} |
  | {通用大模型 X} | {大厂} | {自研} | {通用对话} | {免费 + 订阅} | C 端大众 | {XXX} 万 | {优势} | {短板} |

  【2×2 竞争定位图描述】
  - X 轴：左={通用能力广}，右={垂直场景深}
  - Y 轴：下={轻量易用，开箱即用}，上={重型专业，需实施}
  - 已占位：{竞品 A}在左上（通用+重型）、{竞品 B}在右上（垂直+重型）、{通用大模型}在左下（通用+轻量）
  - **空位**：右下（垂直场景深 + 轻量易用）——客户不想买重型实施，但又要垂直精度。这是本产品的目标位置。
  - 空位为什么没人做：{大厂看不上客单价 / 垂直玩家懒得做产品化 / 开源方案没有运维保障}。
  ```

### 3.5 技术趋势与路线图（含 Hype Cycle 定位）

- **这一节写什么**：判断关键技术现在处于 Gartner Hype Cycle 的哪个阶段（启动期/期望膨胀期/泡沫谷底期/复苏期/生产力平台期），并给出未来 12-24 个月的技术路线图建议。
- **颗粒度要求**：至少覆盖 5 项关键技术（如推理模型、Agent、多模态、长上下文、RAG、国产算力），每项给"当前阶段 + 成熟时间 + 对本产品影响"。最后给一段"技术选型建议"（自研/调用 API/开源微调的取舍）。
- **填写要点**：
  - **Hype Cycle 定位要诚实**。很多 PM 把"还在期望膨胀期"的技术当成"已经成熟"来写，结果产品做出来技术还没跟上。
  - **推理模型（o1/R1 类）**：适合复杂任务，但延迟高、成本贵；本产品是否需要？
  - **Agent / 多智能体**：框架多但稳定性差，0→1 阶段建议"固定 Workflow + 少量 Agent"，不要上通用多智能体。
  - **RAG 2.0 / GraphRAG / MCP**：哪些已可商用、哪些还在论文里。
  - **成本曲线**：API 单价每季度下降多少？这决定你的毛利结构。
  - **技术选型建议**：0→1 阶段默认"调用第三方 API + 少量开源模型微调"，不要自建基础模型。
  - **常见坑**：把所有新技术都写成"本产品要采用"。技术路线图要回答"哪些现在用、哪些等、哪些不碰"。
- **示例片段**：
  ```
  【关键技术 Hype Cycle 定位】
  | 技术 | 当前阶段 | 预计成熟 | 对本产品影响 |
  |---|---|---|---|
  | {推理模型} | 复苏期早期 | 已可用，但贵 | 复杂任务用，简单任务不用，控制成本 |
  | {Agent 工具调用} | 期望膨胀期 | 12-18 个月 | 0→1 用固定 Workflow，不上通用 Agent |
  | {多模态生成} | 期望膨胀期后段 | 已可用但质量不稳 | 不作为 MVP 核心，作为增强 |
  | {长上下文 1M} | 启动期 | 12 个月 | 暂不依赖，用 RAG 替代 |
  | {RAG + 结构化} | 生产力平台期 | 已成熟 | 本产品核心技术栈 |
  | {国产算力} | 复苏期 | 已可用，性能 60-80% | 私有化客户备选，不做首选 |

  【技术选型建议】
  - MVP 阶段：{调用 2 家第三方模型 API + 开源 RAG 框架}，不自研基础模型。
  - 6 个月后：对高频场景做小模型蒸馏/微调，降低 30-50% 推理成本。
  - 12 个月后：评估是否自建垂直小模型，但前提是数据壁垒已建立。
  ```

### 3.6 投融资与资本动态

- **这一节写什么**：近 4 个季度全球 AI 融资趋势、大额融资事件、独角兽名单、钱在往哪几个细分赛道流。最后给"对本产品融资节奏的启示"。
- **颗粒度要求**：至少 3 张表——融资总量趋势、近 1 年大额事件、独角兽名单。最后一段写清"本产品应在什么时间窗口融什么轮"。
- **填写要点**：
  - **融资总量**：全球/中国分开看；笔数 vs 金额分开看（笔数降但金额升 = 钱在往头部集中）。
  - **大额事件**：列出 >1 亿美元的融资，标注投资方和赛道。
  - **资本热点**：钱在往哪几个细分赛道流（Agent？垂直应用？算力？具身智能？）。热点 = 竞争对手多，但也容易融资。
  - **对本产品的启示**：如果本赛道是资本热点，融资容易但竞争激烈；如果是冷门，融资难但没人抢。要给出"什么时候融、融多少、估值预期"。
  - **常见坑**：只列融资新闻，不分析"对本产品意味着什么"。资本动态是用来判断窗口期的，不是用来凑热闹的。
- **示例片段**：
  ```
  【近 4 季度融资趋势】
  | 季度 | 全球 AI 融资总额 | 笔数 | 平均单笔 | 头部集中度 |
  |---|---|---|---|---|
  | {2025Q4} | {XXX} 亿美元 | {N} | {X} | CR5 占 {XX%} |
  | ... | ... | ... | ... | ... |

  【近 1 年大额融资（>1 亿美元）】
  | 公司 | 轮次 | 金额 | 估值 | 投资方 | 赛道 |
  |---|---|---|---|---|---|
  | {公司 A} | {B} | {X} 亿 | {XX} 亿 | {机构} | {赛道} |

  【资本热点判断】
  - 钱明显流向：{Agent 基础设施 / 垂直行业应用 / 算力}
  - 钱在离开：{通用聊天 C 端 / 纯模型层创业}
  - 对本产品启示：本赛道属于{资本热点/冷门}，建议{6 个月内启动天使轮 / 12 个月后等数据再融 A 轮}。
  ```

### 3.7 风险与合规

- **这一节写什么**：分四类风险——监管合规风险、技术风险、供应链风险、商业风险。每类给"风险描述 + 发生概率 + 影响程度 + 缓解措施"。
- **颗粒度要求**：每类至少 2-3 条风险；每条给高/中/低概率 × 高/中/低影响；缓解措施要可执行（不是"加强风控"）。
- **填写要点**：
  - **监管风险**：备案、内容安全、数据出境、知识产权（训练数据版权、生成内容版权）、行业准入。
  - **技术风险**：幻觉、越狱/Prompt 注入、模型迭代过快导致产品壁垒丧失（今天做的功能明天模型原生支持了）。
  - **供应链风险**：GPU 断供、模型 API 涨价/停服、国产算力成熟度。
  - **商业风险**：价格战、大厂免费策略挤压、客户付费意愿不足、销售周期超预期。
  - **最容易被忽略的风险**：模型原生能力升级——你花 3 个月做的"长文档总结"功能，下一代模型原生支持了，你的产品就没了。这条必须写。
  - **常见坑**：风险写成"市场波动大、竞争激烈"这种废话。要写到具体事件（"若 {某模型厂商} 推出免费版，本产品 C 端收入可能下降 X%"）。
- **示例片段**：
  ```
  | 风险类别 | 风险描述 | 概率 | 影响 | 缓解措施 |
  |---|---|---|---|---|
  | 监管 | {未备案即上线 C 端服务} | 中 | 高（下架+罚款） | MVP 仅做 B 端私有化，备案启动后再上 C 端 |
  | 监管 | {训练/生成内容版权纠纷} | 中 | 中 | 仅用授权数据；用户生成内容加免责声明；预留版权准备金 |
  | 技术 | {模型原生能力升级，本产品功能被替代} | 高 | 高 | 壁垒建立在{垂直数据/工作流/销售渠道}上，不建立在"模型做不到"上 |
  | 技术 | {幻觉导致客户决策错误} | 中 | 高 | 高风险场景强制人工复核；引用溯源；低置信度拒答 |
  | 供应链 | {模型 API 涨价 2-5 倍} | 中 | 中 | 双供应商架构；6 个月内启动小模型蒸馏降本 |
  | 商业 | {大厂免费版切入本场景} | 高 | 中 | 不做 C 端；B 端付费场景靠{实施/集成/数据壁垒}防御 |
  ```

### 3.8 结论与建议（赛道打分 + 切入点 + 3 假设 + 30/60/90 天）

- **这一节写什么**：这是报告的落脚点。五维打分表 → 推荐切入点 → 3 个 MVP 关键假设 → 30/60/90 天行动计划。
- **颗粒度要求**：五维打分（市场规模、增速、竞争激烈度、政策友好度、技术成熟度）每项 1-5 分，加权总分；切入点写清"做哪个场景、哪类客户、什么技术路线、什么商业模式"；3 个假设必须可证伪；30/60/90 天计划每周有明确产出。
- **填写要点**：
  - **五维打分**：不要所有维度都打 5 分。打分的意义是暴露短板。总分 ≥3.5 才建议进入。
  - **推荐切入点**：必须是一个具体场景，不是"做 AI + 某行业"。例如"为{某行业 100-500 人规模企业}的{某岗位}自动生成{某类文档}，年付 {X} 万元"。
  - **3 个 MVP 关键假设**：每个假设必须可证伪（"目标客户愿意年付 X 万元"、"AI 生成质量人工修改率低于 Y%"、"销售周期短于 Z 个月"）。
  - **30/60/90 天计划**：
    - 30 天：完成种子客户访谈（≥10 家）、拿到 3 家付费意向、技术可行性验证。
    - 60 天：MVP 上线（最小可用版本）、5 家种子客户试点、收集真实使用数据。
    - 90 天：根据数据 Go/Pivot/Stop；若 Go，启动融资或扩大团队。
  - **常见坑**：30/60/90 天计划写成"加强市场调研、深入分析需求"。这不是计划，是愿望。
- **示例片段**：
  ```
  【赛道吸引力五维打分】
  | 维度 | 权重 | 得分（1-5） | 加权 | 说明 |
  |---|---|---|---|---|
  | 市场规模 | 20% | {4} | {0.8} | {XXX} 亿元，够大 |
  | 增速 | 25% | {4} | {1.0} | CAGR {XX%} |
  | 竞争激烈度（越不激烈越高分） | 20% | {3} | {0.6} | 头部 3 家，但垂直场景有空位 |
  | 政策友好度 | 15% | {3} | {0.45} | 需备案，但 B 端私有化可豁免 |
  | 技术成熟度 | 20% | {4} | {0.8} | RAG/工作流已成熟，Agent 暂不用 |
  | **总分** | 100% | — | **{3.65}** | 建议进入 |

  【推荐切入点】
  - 场景：{某行业某岗位某类任务}
  - 客户：{100-500 人规模，年付能力 {X-X} 万}
  - 技术：{第三方模型 API + RAG + 固定 Workflow}
  - 商业模式：{年付 SaaS + 实施费}

  【3 个 MVP 关键假设】
  1. {至少 10 家目标客户中，≥5 家愿意为该功能年付 ≥X 万元}——30 天内验证。
  2. {AI 生成结果人工修改率 <Y%，且单次任务耗时从 Z 小时降到 <1 小时}——60 天内验证。
  3. {从首次接触到签约周期 <N 个月}——90 天内验证。

  【30/60/90 天计划】
  | 阶段 | 目标 | 关键产出 | Go/No-Go 闸门 |
  |---|---|---|---|
  | 30 天 | 验证客户付费意愿 | ≥10 家访谈、≥3 家付费意向书 | 无付费意向则 Stop |
  | 60 天 | 验证产品价值 | MVP 上线、5 家试点、修改率/耗时数据 | 修改率 >Y% 则 Pivot |
  | 90 天 | 验证商业闭环 | ≥3 家签约、回款到账 | 回款不足则不扩团队 |
  ```

### 3.9 附录：数据来源与口径说明

- **这一节写什么**：所有引用数据的来源、年份、口径、链接；本报告自行测算的数字，写出计算公式与假设；列出参考报告清单。
- **颗粒度要求**：每一个正文出现的数字都能在附录找到出处；测算公式写到能被第三方复算；标注数据截止日期。
- **填写要点**：
  - **数据截止日期**：AI 行业数据每季度变，必须写清"本报告数据截至 {YYYY 年 MM 月}"。
  - **口径说明**：全球 vs 中国、企业支出 vs 用户付费、CAGR 区间（2025-2028 还是 2026-2030）。
  - **测算公式**：TAM/SAM/SOM 的每一步推导。
  - **参考报告清单**：所有引用的报告/文章/榜单，附链接。
  - **常见坑**：附录只列参考报告名字，不写口径。决策者质疑数字时，这一节就是你的辩护词。
- **示例片段**：
  ```
  【数据截止日期】2026 年 10 月
  【口径说明】
  - 全球市场规模：采用 IDC 2026 年 9 月《Worldwide AI Spending Guide》口径，含基础设施+模型+应用。
  - 中国市场规模：采用信通院 2026 年《人工智能发展报告》口径，仅含生成式 AI。
  - CAGR 区间：2026-2030 年。
  - MAU：QuestMobile 2026 年 9 月，月活跃用户去重。

  【TAM/SAM/SOM 测算公式】
  - TAM = 中国{行业}IT 支出（{XXX} 亿元，来源 {IDC}）× AI 可替代比例（{XX%}，本报告访谈 {N} 位行业专家估算）
  - SAM = TAM × 可服务地域比例（{XX%}）× 可服务客户数比例（员工 100-1000 家企业占比 {XX%}）× 可做场景比例（{XX%}）
  - SOM = 3 年目标客户数（{N} 家）× 渗透率（第 1 年 5%、第 2 年 15%、第 3 年 30%）× 客单价（{X} 万元/年）

  【参考报告清单】
  1. McKinsey《State of AI 2026》...
  2. IDC《Worldwide AI Spending Guide 2026》...
  3. 信通院《人工智能发展报告 2026》...
  4. ...
  ```

## 四、不同产品类别的差异化要点

### A 类（对话式 AI / Agent 产品）
- **3.5 技术趋势是核心**：重点写 Agent 技术成熟度（多智能体框架、MCP 协议、工具调用稳定性）、Hype Cycle 定位要诚实——Agent 多在期望膨胀期，0→1 不要上通用多智能体。
- **3.2 市场规模**：分 C 端陪伴/助手 vs B 端 Agent 两个市场。C 端写 MAU/付费率；B 端写"企业 RPA + AI Agent"的替代空间。
- **3.4 竞争格局**：直接竞品矩阵重点对比"人设丰富度、多轮对话能力、Tool use 生态、长期记忆能力"。
- **3.7 风险**：加厚"模型原生 Agent 能力升级"风险——今天你做的 Agent，明天模型原生支持了。壁垒必须建在垂直工作流/数据/销售渠道上。
- **3.8 切入点**：C 端陪伴赛道不建议 0→1 进入（大厂烧钱），优先 B 端垂直 Agent 或 C 端小众角色。

### B 类（RAG 知识库 / 问答产品）
- **3.5 技术趋势**：重点写 RAG 技术栈成熟度（已进入生产力平台期）、向量数据库市场、GraphRAG/Memory/RAG 2.0 处于哪个阶段。
- **3.2 市场规模**：企业知识库渗透率（国内 <X%）、知识管理软件市场规模、RAG 替代传统搜索/FAQ 的空间。
- **3.4 竞争格局**：直接竞品矩阵重点对比"知识库支持格式、召回准确率（Recall@5）、引用溯源、权限管理、更新回滚机制"。
- **3.1 P 政策**：加厚数据合规——企业知识库涉及内部文档/PII，私有化部署是刚需。
- **3.8 切入点**：不做通用知识库（被飞书/钉钉/Notion 挤压），切垂直行业知识库（法律/医疗/金融/制造）。

### C 类（AIGC 多模态生成产品）
- **3.5 技术趋势**：重点写多模态生成模型成本曲线（图像/视频/音频每季度降价幅度）、生成质量演进、版权合规风险。
- **3.2 市场规模**：分"通用生成工具" vs "垂直应用"——通用工具被大厂免费挤压，垂直应用（设计/营销/电商/影视）有付费空间。
- **3.4 竞争格局**：直接竞品矩阵重点对比"提示词模板丰富度、生成速度、输出分辨率/时长、单次成本、风格库、商用授权"。
- **3.7 风险**：版权风险是头号——训练数据版权、生成内容版权、肖像权、音乐版权。必须写清缓解措施。
- **3.8 切入点**：不做通用文生图/文生视频（大厂战场），切垂直场景（电商商品图、营销短视频、游戏素材）。

### D 类（AI 评测平台 / 内部工具）
- **3.5 技术趋势**：重点写评测工具生态（LLM-as-Judge 技术成熟度、自动评测框架 RAGAS/TruLens/ARES）、Hype Cycle 定位。
- **3.2 市场规模**：分"内部工具"（不对外，自服务）vs "商业化评测平台"。商业化市场小但增长快。
- **3.4 竞争格局**：直接竞品矩阵重点对比"评测集规模、自动评分能力（LLM-as-Judge 一致性）、bad case 管理、版本对比功能、私有化部署"。
- **3.8 切入点**：优先做内部工具（自用），验证价值后再考虑商业化。不要一上来就做对外评测平台。

### E 类（B 端 SaaS / 传统产品 AI 化）
- **3.1 PEST 加厚**：P 政策（行业准入、数据合规、招投标要求）、E（行业 IT 预算、数字化转型预算）、S（采购决策链）。
- **3.3 产业链**：改画"行业价值链"——现有 IT 厂商（ERP/OA/CRM）怎么赚钱、AI 能切哪几个环节。
- **3.4 竞争格局**：直接竞品不仅要列 AI 原生玩家，还要列传统软件厂商（他们正在 AI 化）和实施商。
- **3.2 市场规模**：TAM/SAM/SOM 必须写清客户付费意愿（客单价、销售周期、续费率）。B 端市场规模不是问题，问题是你能不能卖进去。
- **3.8 切入点**：选 1 个行业 × 1 个场景 × 1 类客户做深，不要跨行业。销售渠道和实施能力是壁垒，不是技术。
