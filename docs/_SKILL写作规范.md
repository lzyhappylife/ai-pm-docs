# SKILL 写作规范（所有子代理必须严格遵循）

## 产品分类体系（每份SKILL都要标注适用类别）

| 类别 | 名称 | 代表项目 | 核心特征 |
|------|------|---------|---------|
| A | 对话式AI / Agent产品 | 小手机（AI角色陪伴）、AI面试Agent、销售陪练 | 多轮对话、Tool use、长期记忆、人设/角色、主动触发 |
| B | RAG知识库 / 问答产品 | 店智参谋（餐饮经营助手） | 知识库检索、引用溯源、结构化回答模板、Metadata标注 |
| C | AIGC多模态生成产品 | AI婚纱馆 | 提示词组装、多模型fallback、结果质量控制、成本工程 |
| D | AI评测平台 / 内部工具 | 面智评 | Golden Set、LLM-as-Judge、bad case闭环、版本回归 |
| E | B端SaaS / 传统产品AI化 | 美团收银+AI功能 | 商户场景、功能迭代、工单驱动、数据看板 |

## 每份SKILL的标准结构（必须严格遵循，到三级标题）

```markdown
# 【文档名称】SKILL

> **适用产品类别**：A / B / C / D / E（列出哪些类别适用，并用一句话说明为什么）
> **文档目的**：这份文档解决什么问题？给谁看的？
> **撰写时机**：在产品流程的哪个阶段写？

## 一、撰写前需要收集的资料清单
分大类列出（用户侧 / 业务侧 / 技术侧 / 数据侧），每类下列具体条目。

## 二、资料来源渠道
哪些信息从哪里获取？（用户访谈/竞品官网/技术文档/数据平台/埋点后台/工单系统等）

## 三、完整框架结构（到三级标题）
按参考文档的真实章节，逐个章节写：
### 3.x 章节名
- **这一节写什么**：1-2句话说明
- **颗粒度要求**：写到什么深度算合格？（例如："功能需求要写到每个交互节点，不能只写'用户可以对话'"）
- **填写要点**：关键注意事项、常见错误
- **示例片段**：从参考文档中提炼的通用化示例（去掉项目特定内容，用{占位符}）

## 四、不同产品类别的差异化要点
- **A类（对话式Agent）**：写这节时特别注意什么？
- **B类（RAG知识库）**：写这节时特别注意什么？
- **C类（AIGC生成）**：写这节时特别注意什么？
- **D类（评测平台）**：写这节时特别注意什么？
- **E类（B端SaaS）**：写这节时特别注意什么？
（不适用的类别写"不适用"或一句话说明为什么不适用）

## 五、完成度 Checklist
10-15个勾选项，写完对照打勾。例如：
- [ ] 核心功能写到了交互级颗粒度
- [ ] 非功能需求（性能/成本/安全）已列出
- [ ] 埋点需求已明确到事件名
- [ ] 验收标准可量化

## 六、AI生成 Prompt 模板
一个可以直接复制使用的Prompt：
```

项目背景：{项目背景}
目标用户：{目标用户}
核心功能：{核心功能}
技术约束：{技术约束}
...

要求：
1. 严格按照【文档类型】的标准框架结构撰写
2. 每个章节写到【颗粒度要求】
3. 标注哪些地方需要补充实际数据
4. 去具体化：不要使用任何真实产品名、公司名、行业名，全部用{占位符}
```
```

## 硬性要求

1. **先读参考文档再写**：本地已有抓取好的文档JSON，优先读取；本地没有的用 `lark-cli docs +fetch --url <飞书链接>` 抓取。
2. **去具体化**：把项目特定内容（产品名、行业、具体数据、公司名）全部替换成通用占位符如{产品名}、{目标行业}、{关键指标}。
3. **颗粒度不能低于参考文档**：参考文档写到了交互级，框架也要写到交互级；参考文档有12章，框架也要有对应的12章。
4. **示例片段必须来自真实参考文档**，不能凭空编造。
5. **输出为独立Markdown文件**，放在指定目录下。
6. **不要在文件中泄露内部ID、token等技术信息**。
