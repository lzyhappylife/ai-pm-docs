# 【多品竞品横向对比】SKILL

> **适用产品类别**：A / B / C / D / E 全类别。只要你需要同时摆 3 个以上竞品在一张表里比（选型、立项、版本决策都用），就用这份。它和《03 单品竞品深度分析》是一对：**03 是"扎进去把一个竞品摸透"，这份是"跳出来把 N 个竞品摆在一起比"**。两个都要写，但先写横向对比圈定重点，再对重点竞品做深度分析。
> **文档目的**：解决三个问题——①市面上 N 个候选，到底留哪 K 个继续比；②这 K 个在关键维度上谁强谁弱；③本产品的差异化空位在哪、哪些坑不能踩。读者是产品负责人、研发负责人、立项决策者、市场/销售。
> **撰写时机**：①立项前，从一堆竞品里圈定直接对手；②版本规划前，对比新功能要不要做；③选型时（模型/供应商/框架）横向比。一般花 3-5 天，写完冻结 1 个季度。

---

## 〇、先想清楚：你是哪种横向对比？

| 对比类型 | 你要回答的问题 | 候选竞品数量 | 典型场景 |
|---|---|---|---|
| **类型 A：赛道扫描型** | "这个赛道里都有谁？谁是直接对手？" | 10-30 个 → 筛到 5-8 个 | 立项前 |
| **类型 B：决策选型型** | "这 5 个里选哪个当标杆/当对标？" | 5-8 个 | 版本规划、功能对标 |
| **类型 C：采购选型型** | "3 个供应商/模型/框架，我们买哪个？" | 3-5 个 | 技术选型、采购决策 |

**裁剪规则**：
- 类型 A 必写 3.1 目的范围 + 3.2 筛选逻辑 + 3.3 维度总览 + 3.4 主表 + 3.10 启示。
- 类型 B 在 A 基础上加 3.5 雷达图 + 3.8 SWOT + 3.9 定位图。
- 类型 C 加 3.6 定价对比 + 3.7 用户画像 + 3.11 附录截图。
- **铁律**：无论哪种类型，3.4 主对比表每一格必须填具体信息（数字、功能名、价格），**禁止填"较好/一般/一般般"**——这是横向对比表最常见的废表。

## 一、撰写前需要收集的资料清单

### 1.1 候选池侧
- 赛道内所有玩家（N 个候选）：官网、应用商店、媒体报道、融资新闻
- 每个玩家的一句话定位（从官网首页抄，不要自己编）
- 每个玩家的大致体量（MAU/客户数/估值/收入预估）

### 1.2 功能侧
- 每个竞品的核心功能清单（从官网功能页、产品手册、上手体验中整理）
- 关键交互流程（注册→核心任务→产出→导出）
- AI 特有能力：模型选型、Prompt 工程、RAG 知识库、Agent 工具调用、多模态

### 1.3 定价与商业模式侧
- 免费额度（每日/每月多少）
- 个人订阅价（月付/年付，人民币/美元）
- 企业版定价（按席位？按量？私有化报价？）
- 按量价（每千 token / 每次生成 / 每 GB）
- 是否有 API、API 价格

### 1.4 用户与市场侧
- 目标用户画像（从官网"客户案例"、用户评价、社群反馈推断）
- 主要使用场景（写作/编程/客服/设计/营销……）
- 用户评价（应用商店评分、差评关键词、社群吐槽）
- 市场表现（MAU、下载量、融资、标杆客户）

### 1.5 本产品侧
- 本次对比要回答的决策问题（立项？选型？功能规划？）
- 本产品当前定位、目标用户、核心功能
- 本产品已知短板（对比时才能找到"避坑点"）

## 三、完整框架结构（到三级标题）

### 3.1 对比目的与范围

- **这一节写什么**：开篇用 2-3 句话讲清——为什么要做这次横向对比（要回答什么决策问题）、对比哪几个、**不对比哪几个、为什么不对比**。
- **颗粒度要求**：必须写清"这次对比要支撑什么决策"（立项 Go/No-Go？版本功能优先级？技术选型？）；入对比清单写清名字；**不入对比清单也要列 3-5 个"我们知道但不对比"的，并写一句为什么**（例如"不对比 {通用大模型 X}，因为它不做{垂直场景}"）。
- **填写要点**：
  - **不对比清单和对比清单一样重要**。它证明你做过功课，不是只看知名产品。
  - 决策问题要具体（"判断是否进入 {某垂直场景}"），不要写"了解一下市场"。
  - 对比时间窗要写清（"本次对比基于 2026 年 10 月各产品官网与实测版本"），因为 AI 产品一个月变一次。
- **示例片段**：
  ```
  【对比目的】
  本次横向对比为回答一个决策问题：{在 {某垂直场景} 中，本产品应该对标谁、差异化空间在哪、哪些坑要避}。
  对比结果将直接用于{立项评审 / 版本功能规划 / 技术选型}。

  【入对比清单（5 个）】
  {竞品 A、竞品 B、竞品 C、竞品 D、竞品 E}

  【不入对比清单（但已评估）】
  - {通用大模型 X}：不做{垂直场景}，只做通用对话，作为替代品列在附录。
  - {某开源项目}：无商业化团队，不计入直接竞争。
  - {某海外产品}：中国大陆不可访问，仅作技术参考。

  【对比时间窗】
  2026 年 10 月，基于各产品官网、定价页与本人实测版本。
  ```

### 3.2 竞品筛选逻辑（从 N 个候选砍到 K 个）

- **这一节写什么**：候选池一开始可能有 15-30 个，要写清"按什么标准砍到 5-8 个入主表"。
- **颗粒度要求**：列出候选池全名单（哪怕只是名字），再写 3-4 条筛选标准，每条标准给"通过/淘汰"的判断结果。最后剩 5-8 个进入主表。
- **填写要点**：
  - **筛选标准要可操作**：例如"必须在中国大陆可访问"、"必须有付费版本（免费玩具不算直接对手）"、"必须服务{目标客户群}"、"最近 6 个月有更新"。
  - **淘汰理由要具体**：不要写"不合适"，要写"不服务{目标客户}、只做{C 端消费者}、产品 1 年没更新"。
  - **候选池怎么凑齐**：从四个渠道凑——①应用商店/分类榜搜关键词；②媒体报道/融资新闻里提到的玩家；③客户/销售告诉你"你们和谁谁谁比过"；④竞品官网的"客户案例"里看他们对标谁。四个渠道交叉去重，一般能凑出 15-30 个。
  - **为什么必须留 5-8 个而不是 3 个**：3 个太少，看不出赛道格局；10 个以上太多，主表没法看。5-8 个是"既有头部、又有新锐、还有 1-2 个长尾"的最佳数量。
  - **常见坑 1**：跳过筛选过程，直接给 5 个竞品。决策者会问"那 {某知名产品} 为什么不在？"——这一节就是答案。
  - **常见坑 2**：只列海外知名产品，不列国内真实对手。国内产品才是你真正要面对的竞争对手，海外产品更多是"技术参考"而不是"直接对手"。
  - **常见坑 3**：把"通用大模型"（ChatGPT/豆包/Kimi）也算进直接竞品。它们是替代品，不是直接竞品——单独放在"间接竞品与替代品"小节，不要入主表。
- **示例片段**：
  ```
  【候选池（18 个）】
  {竞品 A、B、C、D、E、F、G、H、I、J、K、L、M、N、O、P、Q、R}

  【筛选标准】
  1. 必须服务{目标客户群：某行业某规模企业}
  2. 必须有付费版本（免费/试用版不算直接对手）
  3. 必须在中国大陆可正常访问和使用
  4. 最近 6 个月有版本更新

  【筛选过程】
  | 候选 | 标准 1 | 标准 2 | 标准 3 | 标准 4 | 结果 |
  |---|---|---|---|---|---|
  | {A} | ✓ | ✓ | ✓ | ✓ | 入 |
  | {B} | ✓ | ✓ | ✓ | ✓ | 入 |
  | {C} | ✗（只做 C 端） | — | — | — | 淘汰 |
  | {D} | ✓ | ✗（完全免费） | — | — | 淘汰 |
  | {E} | ✓ | ✓ | ✗（大陆不可访问） | — | 淘汰 |
  | {F} | ✓ | ✓ | ✓ | ✗（1 年没更新） | 淘汰 |
  | ... | | | | | |

  【最终入主表（5 个）】{A、B、G、H、K}
  ```

### 3.3 对比维度总览

- **这一节写什么**：在主表之前，先列出"我们比哪些维度"，并写清每个维度怎么打分/怎么取值。
- **颗粒度要求**：至少 6-8 个维度大类，每个大类下有 2-4 个具体指标。维度要和你的决策问题相关——不要为了全而全。
- **填写要点**：
  - **维度必须服务决策**。如果决策是"要不要做某功能"，那"该功能的实现方式"就是核心维度；如果决策是"选哪个模型"，那"模型选型与价格"就是核心维度。
  - **每个维度写清取值方式**：是打分（1-5）？是具体数字（MAU、价格）？是"有/无"？是一段描述？
  - **AI 产品必比的维度**：模型选型、核心 AI 能力、定价、目标用户、核心场景、优势、短板。
  - **不要为了全而全**。18 个维度听起来很全，但主表会糊成一团。决策者一眼看完的维度上限是 8-10 个。
  - **维度要和你的决策问题挂钩**。如果你的决策是"要不要做企业版"，那"企业功能（SSO/权限/审计）"就是核心维度；如果你的决策是"要不要做 C 端"，那"C 端易用性"就是核心维度。
  - **常见坑**：维度堆了 20 个，但每个维度都没写取值方式。主表填的时候每格都是"较强/一般"——这张表就废了。
- **示例片段**：
  ```
  【本次对比维度（7 大类 18 小项）】
  | 维度大类 | 具体小项 | 取值方式 |
  |---|---|---|
  | 产品定位 | 一句话定位、目标用户、核心场景 | 描述 |
  | 核心功能 | 功能清单、关键交互流程 | 有/无 + 描述 |
  | AI 能力 | 模型选型、知识库/Agent/多模态、质量表现 | 描述 + 实测 |
  | 定价策略 | 免费额度、个人版、企业版、API 价 | 具体金额 |
  | 用户与市场 | MAU、下载量、标杆客户、评价 | 数字 |
  | 优势 | 最突出的 1-2 个优势 | 描述 |
  | 短板 | 最突出的 1-2 个短板 | 描述 |
  ```

### 3.4 逐维度横向对比主表（核心）

- **这一节写什么**：这是整份文档的主体。一张大表，行是竞品，列是维度，**每一格填具体信息，不填"较好/一般"**。
- **颗粒度要求**：5-8 个竞品 × 8-10 个维度。每格填具体内容（功能名、数字、流程），不要写"较强"。如果某个维度对该竞品不适用，写"不适用"而不是空着。
- **填写要点**：
  - **这是整张表的灵魂**。很多横向对比表做成"较好/一般/较弱"——这种表没有任何决策价值，因为"较好"的标准是什么？
  - 每格写法：
    - 有/无类：直接写"有"或"无"，加一句功能名。
    - 数字类：直接写数字（价格、MAU、分辨率）。
    - 描述类：写 1-2 句具体事实（"支持上传 PDF/Word/Excel，单文件 ≤50MB"）。
  - **实测过的功能标"实测"，官网看到的标"官网"**。
  - **不要美化竞品**。短板要写真话（"中文回答幻觉率高"、"企业版无 SSO"），这是避坑点。
- **示例片段**（一行一个竞品，列是维度）：
  ```
  | 维度 | {竞品 A} | {竞品 B} | {竞品 C} | {竞品 D} | {竞品 E} |
  |---|---|---|---|---|---|
  | 一句话定位 | {官网首页原话} | {官网原话} | {官网原话} | {官网原话} | {官网原话} |
  | 目标用户 | {某行业某规模企业} | {C 端个人} | {开发者} | {某专业岗位} | {全行业通用} |
  | 核心场景 | {场景 1/2/3} | {写作/问答} | {API 调用} | {专业任务} | {通用办公} |
  | 核心功能 | {功能清单} | {功能清单} | {功能清单} | {功能清单} | {功能清单} |
  | 模型选型 | {自研模型 X} | {第三方 API} | {开源微调} | {自研 + 第三方} | {第三方} |
  | 知识库支持 | {支持 PDF/Word，单文件 50MB}（实测） | {不支持知识库} | {API 支持} | {支持 10 种格式，500MB} | {仅 URL 抓取} |
  | Agent/工具 | {支持工具调用} | {不支持} | {支持自定义工具} | {固定 Workflow} | {基础插件} |
  | 免费额度 | {每日 20 次} | {每月 100 万 token} | {无免费版} | {14 天试用} | {每日 5 次} |
  | 个人版价 | {30 元/月} | {20 美元/月} | — | {99 元/月} | {免费} |
  | 企业版价 | {坐席 200 元/月} | {按量 + 坐席} | {私有化报价} | {报价制} | {免费 + 增值} |
  | MAU（近 30 天） | {XXX} 万 | {XXX} 万 | N/A（API） | {XX} 万 | {XXX} 万 |
  | 标杆客户 | {客户 A/B/C} | 无（C 端） | {开发者社区} | {客户 X/Y} | {大厂自家} |
  | 最突出优势 | {垂直行业数据深} | {价格便宜} | {灵活可定制} | {专业质量高} | {免费量大} |
  | 最突出短板 | {价格贵、实施重} | {无知识库、质量一般} | {无产品化界面} | {价格贵、场景窄} | {质量一般、无企业功能} |
  ```

### 3.5 能力雷达图描述

- **这一节写什么**：把主表中的关键能力维度画成雷达图（或文字描述雷达图形状），让决策者一眼看出"谁是全能型、谁是偏科型"。
- **颗粒度要求**：选 5-6 个关键维度（不要超过 6 个，否则图糊），每个维度给 1-5 分。每个竞品给一段形状描述（"全能型但没突出优势"、"偏科型，在 X 维度极强但 Y 维度弱"）。
- **填写要点**：
  - **打分要基于主表事实**，不是感觉。例如"知识库能力 5 分"是因为它支持 10 种格式 + 500MB + 权限管理。
  - **雷达图的价值在于看出空位**——如果所有竞品在 X 维度都是 2 分，那 X 就是差异化机会。
  - **常见坑**：所有竞品都打 4 分以上。这没有信息量。打分要拉开差距。
  - **分数怎么打**：每个维度定一个 5 分锚点（"5 分 = 行业最好水平；3 分 = 及格线；1 分 = 完全没有"）。不要凭感觉打。
  - **形状描述比分数本身重要**。决策者不看分数，看形状。一句话说清"{A} 是偏科型，{B} 是全能平庸型"，比一堆数字有用。
- **示例片段**：
  ```
  【关键维度打分（1-5 分）】
  | 维度 | {A} | {B} | {C} | {D} | {E} |
  |---|---|---|---|---|---|
  | 垂直场景深度 | 5 | 2 | 3 | 5 | 2 |
  | 易用性 | 2 | 5 | 1 | 3 | 5 |
  | AI 质量 | 4 | 3 | 4 | 5 | 3 |
  | 企业功能（SSO/权限/审计） | 5 | 1 | 2 | 4 | 1 |
  | 价格友好度 | 2 | 5 | 3 | 1 | 5 |
  | 生态/插件 | 3 | 3 | 5 | 2 | 4 |

  【形状描述】
  - {A}：偏科型——垂直深度和企业功能 5 分，但易用性和价格 2 分。定位重型企业客户。
  - {B}：偏科型——易用性和价格 5 分，但企业功能 1 分。定位 C 端个人。
  - {C}：开发者型——生态 5 分，但易用性 1 分。无产品化界面。
  - {D}：偏科型——AI 质量 5 分，但价格 1 分、生态 2 分。定位专业高付费用户。
  - {E}：全能平庸型——所有维度 3-5 分但无突出优势。

  【空位识别】
  所有竞品在"垂直深度（5） × 易用性（5）"这个交叉点都没人——A 和 D 垂直深但难用，B 和 E 易用但不深。这是本产品的潜在位置。
  ```

### 3.6 定价策略对比

- **这一节写什么**：把各竞品的定价模型单独拎出来细比——免费额度、个人版、企业版、按量价、API 价、私有化报价。
- **颗粒度要求**：画一张定价表，每格填具体金额（人民币/美元），并写清"计费单位"（按席位？按 token？按次？）。最后一段总结"谁的定价策略最聪明、谁的最贵、谁是免费兜底"。
- **填写要点**：
  - **免费额度要看"对谁友好"**：每日次数型对轻度用户友好，每月 token 型对重度用户友好。
  - **企业版要问"最低起步价"**：很多企业版报价是"坐席 × 月费"，但最低 50 席起——这对小客户是门槛。
  - **API 价要算"一次任务多少钱"**：不要只看"每千 token 多少美元"，要算"完成一次典型任务消耗多少 token × 单价 = 多少钱"。
  - **常见坑**：只标个人版价格，不标企业版。B 端产品决策者最关心企业版起步价。
- **示例片段**：
  ```
  【定价对比表】
  | 竞品 | 免费额度 | 个人版（月付） | 个人版（年付） | 企业版起步 | API 价 |
  |---|---|---|---|---|---|
  | {A} | 每日 {N} 次 | {XX} 元/月 | {XXX} 元/年（省 X 月） | {X} 万/年起（含{N} 坐席） | {输入 X 元/百万 token，输出 X 元} |
  | {B} | 每月 {N} token | {X} 美元/月 | {XX} 美元/年 | 按量 + 坐席 | 与个人版同价 |
  | {C} | 无免费版 | — | — | {私有化报价} | {X} 美元/百万 token |
  | {D} | 14 天试用 | {XX} 元/月 | {XXX} 元/年 | {报价制} | {报价制} |
  | {E} | 每日 {N} 次 | 免费 | 免费 | {增值服务收费} | 无 |

  【策略总结】
  - {B} 的免费额度最慷慨，但重度用户会被个人版价格劝退。
  - {A} 的企业版起步价 {X} 万/年，是本品类最贵的，但含实施服务。
  - {E} 完全免费，靠增值服务变现——这是大厂打法，创业公司不要跟。
  - 对本产品启示：定价应在 {A} 和 {B} 之间，免费额度给"够试用但不够日常用"，个人版定价 {XX} 元/月，企业版 {X} 万/年起。
  ```

### 3.7 用户画像对比

- **这一节写什么**：每个竞品服务的是哪类用户、在什么场景用、付费意愿如何。
- **颗粒度要求**：每个竞品一行，列"目标人群（职业/规模/地域）/ 典型使用场景 / 付费意愿 / 标杆客户"。
- **填写要点**：
  - **目标人群要具体到职业**（"法律行业 100-500 人规模律所的律师"），不要写"专业人士"。
  - **典型场景要写"用户在哪一步用"**（"起草合同时"、"客服遇到复杂问题时"）。
  - **付费意愿从客户案例推断**：如果全是免费用户，付费意愿弱；如果有企业客户付费，付费意愿强。
  - **常见坑**：把官网"我们服务所有行业"当成目标用户。要从客户案例反推真实付费人群。
- **示例片段**：
  ```
  | 竞品 | 目标人群 | 典型场景 | 付费意愿 | 标杆客户 |
  |---|---|---|---|---|
  | {A} | {某行业 100-500 人企业}的{某岗位} | {起草某类文档时} | 高（年付 X 万） | {客户 A/B/C} |
  | {B} | {C 端个人，学生/白领} | {日常写作/问答} | 低（C 端付费率 X%） | 无（C 端） |
  | {C} | {开发者/技术团队} | {API 集成到自有产品} | 中（按量） | {开发者社区} |
  | {D} | {某专业岗位，高付费意愿} | {专业任务} | 高（个人版也贵） | {专业人士} |
  | {E} | {全行业通用，C 端为主} | {通用办公} | 低（免费为主） | {大厂自家业务} |
  ```

### 3.8 SWOT 对比矩阵（每个竞品一个 SWOT）

- **这一节写什么**：对每个入主表的竞品，写一个 SWOT（优势/劣势/机会/威胁）。
- **颗粒度要求**：每个竞品 4 行，每行 2-3 个要点。S/W 是产品内部属性，O/T 是外部环境。
- **填写要点**：
  - **S/W 基于实测事实**（"S：垂直行业数据深"、"W：价格贵"），不要写"管理团队优秀"这种空话。
  - **O/T 是外部判断**（"O：{某行业}数字化预算增加"、"T：{通用大模型 X} 免费切入"）。
  - **SWOT 的价值在于找"我们能利用对方哪条 W"**。例如 {A} 的 W 是"难用"，那本产品的差异化就是"更易用"。
- **示例片段**：
  ```
  【{竞品 A} SWOT】
  - S（优势）：{垂直行业数据深、企业功能全、标杆客户多}
  - W（劣势）：{价格贵、实施重、易用性差、小客户用不起}
  - O（机会）：{某行业数字化预算增加、{某政策}推动合规}
  - T（威胁）：{通用大模型 X 免费切入、{某开源项目}蚕食低端}

  【{竞品 B} SWOT】
  - S：{价格便宜、易用、C 端用户量大}
  - W：{无企业功能、无知识库、质量一般、无行业深度}
  - O：{C 端 AI 渗透率提升}
  - T：{大厂免费版挤压、用户付费意愿低}
  ```

### 3.9 竞争定位 2×2 图

- **这一节写什么**：画一张 2×2 定位图，X 轴和 Y 轴各选一个关键维度，把 5 个竞品和本产品都放上去。
- **颗粒度要求**：坐标轴要选"对本产品决策最关键的两个维度"（常用组合：通用度×垂直深度、轻量易用×重型专业、C 端×B 端、价格低×价格高）。每个竞品在象限里的位置要写清"为什么在这个位置"。最后标出**本产品建议落在哪个空位**。
- **填写要点**：
  - **坐标轴选择**：不要选"功能多/功能少"这种没意义的轴。要选"影响本产品定位的"轴。
  - **空位 = 机会**。如果某个象限没有竞品，要写清"为什么没人做"——是不赚钱？还是技术做不到？还是没人想到？
  - **本产品位置要和 3.0 执行摘要的切入点一致**，不能前后矛盾。
- **示例片段**：
  ```
  【坐标轴】
  - X 轴：左={通用场景}，右={垂直场景深}
  - Y 轴：下={轻量易用}，上={重型专业}

  【竞品位置】
  - {E}：左下（通用 + 轻量）
  - {B}：左下偏中（通用 + 轻量）
  - {C}：右下偏中（垂直 + 开发者向，不算轻量）
  - {A}：右上（垂直 + 重型）
  - {D}：右上偏左（专业 + 重型）

  【空位】
  - 右下（垂直场景深 + 轻量易用）：无竞品。
  - 为什么没人做：{A} 做垂直但做成重型（因为要企业功能）；{B} 做轻量但不垂直（C 端通用）。
  - **本产品建议落在右下**：垂直场景做深，但保持轻量（SaaS 开箱即用，不做重实施）。
  ```

### 3.10 对本产品的启示（差异化机会 / 避坑 / 可借鉴）

- **这一节写什么**：把前面所有对比收敛成三条结论——①差异化机会在哪（我们做什么不一样）；②要避的坑（哪些对手踩过的坑我们不要踩）；③可借鉴的打法（哪些对手做得好我们可以学）。
- **颗粒度要求**：每条结论 2-4 个要点，要点必须具体（"做垂直但轻量"、"不要做免费 C 端"），不要写"加强产品体验"。
- **填写要点**：
  - **差异化机会**：从 3.5 雷达图空位 + 3.9 2×2 空位推导。
  - **避坑**：从各竞品 W 和 T 推导（"{A} 踩过的坑是实施重，我们不要走定制化老路"）。
  - **可借鉴**：从各竞品 S 推导（"{B} 的免费额度策略值得学，但要调整到对重度用户不友好"）。
  - **启示必须闭环到动作**。不要写"我们要更关注用户体验"，要写"我们要在 F03 功能上做到 {X 秒内出结果}，而竞品 A 需要 {Y 秒}"。
  - **每条启示要标注"来自哪个对比结论"**。例如"（来自 3.5 雷达图空位）"、"（来自 {竞品 A} 的 W）"。
  - **常见坑 1**：启示写成"我们要做得更好"。这不是启示，是口号。
  - **常见坑 2**：启示有 10 条以上。决策者记不住。收敛到 3-5 条核心启示。
  - **常见坑 3**：差异化机会和 2×2 图空位对不上。3.9 说空位在"垂直+轻量"，3.10 却说"我们要做通用平台"——前后矛盾是大忌。
- **示例片段**：
  ```
  【差异化机会（我们做什么不一样）】（来自 3.5 雷达图 + 3.9 2×2 空位）
  1. 垂直场景做深，但保持轻量——不做重实施，SaaS 开箱即用。（空位：右下象限）
  2. 企业功能（SSO/权限/审计）作为标配，而不是付费升级项。（所有竞品企业功能都弱）
  3. 定价在 {A} 和 {B} 之间：免费额度够试用但不够日常用，个人版 {XX} 元/月。（避免 {A} 太贵、{B} 太免费）

  【要避的坑（对手踩过的）】
  1. 不要走 {A} 的重实施路线——销售周期长、小客户用不起。（{A} 的 W：实施重）
  2. 不要学 {E} 的完全免费——创业公司烧不起，且免费用户不是付费客户。（{E} 的 T：大厂打法）
  3. 不要做 {C} 的纯 API——没有产品化界面就没有 C 端/小 B 客户。（{C} 的 W：无产品化）
  4. 不要在 C 端和 {B} 拼价格——{B} 有大厂补贴，创业公司拼不过。（{B} 的 S：价格便宜）

  【可借鉴的打法】
  1. {B} 的免费额度设计（每日次数型）对轻度用户友好，可借鉴。（{B} 的 S）
  2. {D} 的专业质量定位（高价格高付费）证明垂直高付费用户存在。（{D} 的 S）
  3. {A} 的标杆客户打法——早期签下 {N} 家行业头部客户作为案例。（{A} 的 S）
  4. {D} 的 14 天试用策略——比永久免费额度更容易转化付费。
  ```

### 3.11 附录：竞品截图与原文索引

- **这一节写什么**：每个竞品的关键截图（首页、定价页、功能页）、官网原文出处、实测录屏链接。
- **颗粒度要求**：每个竞品至少 3 张截图（首页、核心功能、定价页），标注截图日期。所有正文引用的功能描述/价格，在附录能找到出处。
- **填写要点**：
  - **截图要带日期**。AI 产品改版快，3 个月前的截图可能已经失效。
  - **原文引用要标注 URL**，不要只写"官网"。
  - **实测录屏**：如果有条件，把注册→核心流程→产出的录屏链接放在附录，供复核。
- **示例片段**：
  ```
  【竞品 A 截图】
  - 首页（2026-10-15 截图）：{路径或链接}
  - 功能页（2026-10-15）：{路径或链接}
  - 定价页（2026-10-15）：{路径或链接}
  - 实测录屏（2026-10-15）：{链接}

  【原文索引】
  - 功能描述引自 {竞品 A} 帮助中心：{URL}
  - 定价引自 {竞品 A} 定价页：{URL}
  - 客户案例引自 {竞品 A} 客户案例页：{URL}
  ```

## 四、不同产品类别的差异化要点

### A 类（对话式 AI / Agent 产品）
- **3.4 主表加厚维度**：人设丰富度（角色数量/自定义程度）、多轮对话能力（上下文长度/多轮一致性）、Tool use 生态（支持多少工具/自定义工具）、长期记忆能力（记忆长度/可编辑）。
- **3.5 雷达图**：选"对话流畅度/角色沉浸感/工具能力/记忆能力/易用性/价格"6 维。
- **3.8 SWOT**：重点看"哪些竞品在多轮失控、哪些在角色跳出、哪些在 Prompt 注入上翻车"。
- **3.9 2×2**：常用轴"通用对话 ↔ 垂直角色"、"轻量聊天 ↔ 重型 Agent"。
- **避坑**：不要做"又一个通用聊天助手"——那是大厂战场。差异化在垂直角色/垂直工作流。

### B 类（RAG 知识库 / 问答产品）
- **3.4 主表加厚维度**：知识库支持格式（PDF/Word/Excel/URL/数据库）、召回准确率（Recall@5 实测）、引用溯源（是否可点击原文）、权限管理（部门/文档级）、更新回滚机制。
- **3.5 雷达图**：选"召回质量/引用准确率/格式支持/权限管理/更新效率/价格"6 维。
- **3.8 SWOT**：重点看"哪些竞品在幻觉、哪些在权限越权、哪些在知识更新滞后"。
- **3.9 2×2**：常用轴"通用知识库 ↔ 垂直行业"、"轻量问答 ↔ 重型审核"。
- **避坑**：不要做"又一个通用知识库"——被飞书/钉钉/Notion 挤压。差异化在垂直行业 + 权限深度。

### C 类（AIGC 多模态生成产品）
- **3.4 主表加厚维度**：提示词模板库（数量/分类）、生成速度（首图/首视频时间）、输出分辨率/时长、单次生成成本、风格库数量、商用授权条款。
- **3.5 雷达图**：选"生成质量/速度/成本/风格丰富度/商用授权/易用性"6 维。
- **3.6 定价**：必须算"一次典型任务多少钱"（不是每千 token 价）。
- **3.8 SWOT**：重点看"哪些竞品在版权纠纷、哪些在生成质量不稳、哪些在成本过高"。
- **3.9 2×2**：常用轴"通用生成 ↔ 垂直场景"、"轻量玩具 ↔ 专业生产"。
- **避坑**：不要做通用文生图/文生视频——大厂免费挤压。差异化在垂直场景（电商/营销/游戏）。

### D 类（AI 评测平台 / 内部工具）
- **3.4 主表加厚维度**：评测集规模（题量/分类）、自动评分能力（LLM-as-Judge 一致性）、bad case 管理（归因/修复/复测闭环）、版本对比功能（多版本通过率）、私有化部署支持。
- **3.5 雷达图**：选"评测集质量/自动评分/版本对比/bad case 闭环/私有化/易用性"6 维。
- **3.8 SWOT**：重点看"哪些竞品评测集小、哪些 Judge 不一致、哪些没有 bad case 闭环"。
- **3.9 2×2**：常用轴"内部工具 ↔ 商业化平台"、"通用评测 ↔ 垂直场景"。
- **避坑**：不要一上来做商业化平台——先自用验证。差异化在"垂直场景评测集 + bad case 闭环"。

### E 类（B 端 SaaS / 传统产品 AI 化）
- **3.4 主表加厚维度**：与现有系统集成方式（SSO/API/嵌入）、商户场景深度（行业 know-how）、定价模式（坐席/按量/项目制）、部署方式（SaaS/私有化/混合）、实施周期。
- **3.7 用户画像**：重点写"采购决策链"（老板/CIO/业务部门/采购）和"销售周期"。
- **3.8 SWOT**：重点看"哪些竞品实施重、哪些不支持私有化、哪些行业 know-how 浅"。
- **3.9 2×2**：常用轴"通用 SaaS ↔ 行业垂直"、"SaaS 轻量 ↔ 项目制重实施"。
- **避坑**：不要跨多行业——选 1 个行业做深。销售渠道和实施能力是壁垒，不是技术。

```
你是一名资深 AI 产品经理，正在为一个项目做多品竞品横向对比。
请根据以下项目信息，输出一份完整的、可直接支撑决策的横向对比文档。
```
